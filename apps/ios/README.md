# Hako iOS

首页沿用运动记录的中性色、圆角列表及底部细线顶部 Tab，按「开发工具 / 管理面板 / 金融 / 生活」切换子应用，默认进入开发工具。代码工坊和[瑞士军刀](../../docs/swiss-army-knife.md)归入开发工具；组网管理、青龙面板、云服务器、容器管理、设备管理和路由器归入管理面板；投资记账、加密资产和 [A 股选股](../../docs/stocktrade.md)归入金融；运动记录和使用时间归入生活。从子应用或设置返回时保留当前分类。通用日志入口位于「设置 → 工具 → 日志」。

首页设置按钮左侧的铃铛进入通用「通知」页，按类别显示内容；当前接入「登录请求」，包括管理网页登录、第三方扫码登录／绑定和 OIDC，尚无演示服务提醒或其他虚构消息。点击条目打开原生确认 Sheet。左滑「清除」仅在本机隐藏提醒；右上角「… → 清除全部」需确认。已清除记录按服务器和账号隔离，保存通知 ID 及期限，不保存确认码、nonce 或凭据，原登录请求仍按原期限有效；其他设备不受影响。关闭 Sheet 不清除通知，批准／拒绝成功和过期请求自动移除。前台静默拉取，无首次加载或下拉刷新动画，网络故障保留上次内容和静态错误提示；不自动弹窗、不含后台推送。确认 Sheet 仍需六位码及明确操作，写请求期间仅显示静态状态。详见[通知与登录请求](../../docs/server-oidc.md#手机登录请求通知)。

个人 iPhone 模块化工具箱，Bundle ID：`me.stackli.hako`。SwiftUI + SwiftData，最低 iOS 27，Xcode 27 或更新版本。容器终端使用 SwiftTerm v1.99.2（Swift Package Manager 固定版本）。首页包含「使用时间」模块；提供原始 Logo 和方形 App 图标。

本目录为 Hako 的 iOS 应用，以下命令均从 `apps/ios/` 执行。在仓库根目录先运行 `cd apps/ios`。返回 [仓库说明](../../README.md)。

## 源码目录

- `Hako/App/` 放应用入口、功能注册、主设置和应用更新。
- `Hako/Features/` 按子应用组织业务、界面和连接协议。设备 SSH、云服务器和容器各自维护终端会话。
- `Hako/Shared/` 放共用 UI、终端显示及输入、Hako 服务端连接、GitHub 访问和基础设施。

## 当前功能

- 主应用「设置 → Hako 服务 → Webhook 管理」复用 Sora 登录，支持创建、编辑、启停、重置 Token 和删除通知 Webhook。完整地址只在生成后展示，频率和过期设置收在「更多选项」中。接口与验证见 [Webhook 管理](../../docs/notification-management.md)。

- 「青龙面板」子应用：直接连接已有青龙 OpenAPI，一级 Tab 为任务、脚本、订阅和更多；支持多面板连接、独立两行 Client ID／Client Secret 和可选自定义请求头（默认留空）。支持任务管理与日志、脚本编辑及已保存版本调试、订阅管理；环境变量位于更多，另提供配置文件编辑、只读依赖和日志文件、权限检测。连接与凭据保存于支持 iCloud 同步的系统钥匙串，沿用黑白主色与原生设置入口。接口、边界和验证见 [青龙面板](../../docs/qinglong.md)。

- 「云服务器」子应用：直接通过阿里云 ECS API 管理一台 Linux 实例，支持无公网终端、概览、整机网络趋势、网卡速率、监听端口、当前连接和进程 CPU / RSS 查询。RAM / STS 凭据保存于支持 iCloud 同步的系统钥匙串；系统快照使用已有云助手、Python 3 与 ss，不新增付费服务、自建接口或第三方采集器。不可提供的流量项目不显示。配置、权限、统计口径和验证见 [阿里云 ECS](../../docs/ecs.md)。

- 「容器管理」子应用：直接连接已有 Arcane 服务，独立配置地址和 API Key（保存于支持 iCloud 同步的系统钥匙串），支持多 Docker 环境、完整分页、搜索与状态／更新筛选、Compose 分组、容器详情、CPU／内存使用率和网络上下行速率、实时日志与日志导出、启停重启及删除。点击环境卡片的主机名称行查看「主机信息」，右侧下拉按钮切换服务器；支持查看本地或远程主机的实时 CPU、内存、磁盘和可用 GPU 指标，以及系统、Docker 信息。「文件」Tab 支持浏览 Compose 项目目录及子目录，查看和修改 YAML、`.env` 及其他文本文件；二进制仅显示文件信息，保存不会自动部署或重启。更新入口为「拉取镜像并重新部署」，重建后跟随新容器 ID；写操作超时不自动重试，需先刷新状态核对。按 Arcane v2.17.1 接口实现，权限、HTTP 选项和验收说明见 [Arcane 容器管理](../../docs/arcane.md)。

- 设备监控右上角滑杆图标（`slider.horizontal.3`）打开设备监控设置，可切换 Agent 和设置默认设备；有设备时在列表标题右侧用加号添加 Agent，空列表保留文字添加入口。设备详情保留下拉刷新，采用运动记录的细下划线标签栏。顶部显示前四个可排序页面和固定的「终端」，其余从右侧「更多」切换。在设备监控设置的「页面排序」区块拖动行尾手柄，松手即按服务器、账号和设备保存本机顺序。系统页使用 ECS 同款 CPU 和内存仪表盘展示当前采样，并显示物理网卡实时上下行速度。Codex 页内切换处理中会话与最近 7 天统计，调用数与 Token 在同一双轴分组柱状图展示，点击日期悬浮查看当天完整数字。历史用量提示与时区、采集时间放在默认折叠的“数据说明”中。每次发送任务/消息计 1 次，不累计内部模型迭代，旧 Agent 未标明用户调用口径时提示更新。按设备时区统计，旧版估算、明细缺失和运行状态不可用均明确提示；需更新支持此能力的 Windows Agent，服务端无需新增业务接口。详见 [设备监控协议](../../docs/device-monitoring.md) 与 [Codex 用量采集](../../docs/codex-usage.md)。

- 设置交互：设置页只展示功能入口、应用更新和构建状态，不提供保存按钮。「服务器与登录」「扫码登录」「GitHub 配置」均以 sheet 打开；服务器和 GitHub 配置只在点击右上角勾号后保存，保存成功关闭 sheet，验证或保存失败则保留输入。点击关闭或下拉关闭有修改的配置 sheet 时，弹窗选择继续编辑或放弃并关闭；输入不会自动保存。扫码 sheet 只提供关闭按钮，网页登录仍须在核对页明确确认。设备监控与扫码页中的服务器配置快捷入口也使用同一 sheet。
- Hako 主应用服务：在「设置 → 扫码登录」批准 Hako 网页登录；在「设置 → 服务器与登录」配置服务器、账号、本机公钥及登录管理。使用 Secure Enclave P-256 密钥，公钥在服务端文件登记后签名登录。所有 Console 都是管理员，无密码或 TOTP；本机凭据自动续期直到退出或撤销。「已登录设备」统一显示 Console 和有效网页会话，支持下拉刷新和单独移除网页登录；Console 项仅查看，不提供远程撤销入口，本机退出在「服务器与登录」操作。已登录时点击「扫码登录」打开相机，也可粘贴并解析请求；未配置、未登录或凭据待验证时先引导服务器配置与登录，验证后自动进入扫描。核对服务器、来源 IP 及两端确认码后确认或拒绝，无需额外 Face ID、Touch ID 或设备密码。相机权限只在打开扫描器时申请，相机不可用仍可粘贴；只接受当前服务器的请求，批准仅对原浏览器有效。共用连接、身份和会话位于 `Hako/Shared/HakoServer/`，扫码及登录管理位于 `Hako/Features/ServerManagement/`，沿用已有 Keychain 与配置键，升级保留身份和会话。部署见 [服务端说明](../server/README.md)，协议见 [Hako 服务器认证协议](../../docs/server-authentication.md)。
- 「设备监控」子应用：复用主应用的 Hako 服务器登录，通过 WebSocket 登记 Agent、查询在线状态和按设备能力调用。设备详情的「实时刷新」默认关闭，勾选后接收 Agent 推送的系统指标、Codex 任务变化和监听端口。Git 标签按需查看 `~/Code` 仓库、远程地址和提交状态，支持选择文件创建提交并单独确认推送。终端只需配置 Windows SSH 账号和密码，首次连接展示主机指纹，点击「信任并连接」后保存到钥匙串再登录；后续自动校验，指纹变化时拒绝连接。首次信任需服务端 0.2.2，Agent 无需为此升级。协议见 [设备监控协议](../../docs/device-monitoring.md)。

- 读取手机当前时区最近 7 个完整自然日（不含今天），按系统的总活动时长统计，汇总各 App 的时长并取前五名。本地已有日期跳过，缺失日期才读取并插入；单日读取失败不阻塞其他日期，已成功记录会保存并同步，失败日期下次重试。
- SwiftData 本地持久化（SQLite）。采集汇总完成后，总时长及各 App 时长先四舍五入到整数秒再保存，GitHub 恢复的新记录也使用相同精度。先保存再上传，网络失败不会删除本地记录；「合并本地与 GitHub 记录」按日期双向补齐，并将合并结果保存到本地，无需屏幕使用时间授权。
- GitHub GraphQL `createCommitOnBranch`：`data/screen-time/2026.csv`，每年一份、每天一行；时长单位为秒，共 13 列，包含日期、时区、总时长及 5 组 bundle ID、时长，不导出名称。不足 5 个时留空。
- 读取远端 CSV 后按日期合并、排序；仅补入远端缺失日期，已有日期的整行保持不变；使用 `expectedHeadOid` 校验分支，遇到 `STALE_DATA` 重新读取并合并，最多尝试 3 次；无缺失日期时不重复提交。远端格式错误停止覆盖。
- 单独合并会扫描 `data/screen-time/` 下全部年度 CSV，合并远端年份与本地年份；本地为空或缺少整年时也能恢复历史记录。本地独有日期补到 GitHub，远端独有日期保存到本地；同一天内容冲突时以 GitHub 整行记录为准，保留匹配 bundle ID 的本地 App 名称和 token。每个年度成功后保存，后续年度失败不会丢失已经保存的记录；双方均为空时提示先采集。无效日期、时区或时长会停止该年度合并。
- 合并结果分别显示本地新增、GitHub 新增、本地更新的天数。时长按 CSV 的整数秒精度比较；历史本地记录仅小数精度、App 名称或 token 不同不算更新，也不覆盖这些相同的历史记录。数据相同时本地更新为 0；GitHub 新增仅统计本次成功提交补入的日期，并发重试时其他写入者补入的日期不计入。
- 新提交由 GitHub 自动签名，返回后检查 `isValid` 和 `wasSignedByGitHub`；如果尚未确认签名，会明确提示数据已提交及对应 commit ID，不冒充已验证。已有提交不重写。提交标题示例：`Update screen-time: 2026-10-08 ~ 2026-10-14`，正文列出本次实际新增日期，单日则仅显示该日期。
- 系统快捷指令统一使用「同步 Hako 数据」。使用时间回调负责读取、本地保存和 GitHub 同步。双向合并入口保留在 App 内。
- GitHub Token 仅存储于设备 Keychain，不写入 CSV、UserDefaults 或日志。
- 设置页「构建进度」进入时查询当前标签，右上角刷新按钮只更新当前标签。设置页可见且 App 在前台时，排队或执行中的任务每 5 秒刷新。没有进行中的任务时停止轮询。「GitHub」可下拉切换 iOS、服务端和 Windows，查看所选工作流在 `stacklix/hako` 主分支的最新运行、触发时间和当前步骤，也可打开对应的 GitHub 运行。私有源码仓库要求已保存的 Token 具备该仓库的 Actions 读取权限。构建进度与已发布的可安装版本分别显示。
- 设置 → 应用更新显示当前版本和构建号。仅当已发布构建号高于当前安装版本时显示绿色图标的「安装最新版」，同行展示最新版本号和构建号，下一行展示本地时区的构建时间；点击直接发起系统 OTA 安装。「查看下载页面」始终保留，可打开 [Ad Hoc 分发页](https://stacklix.github.io/hako/) 查看版本信息或下载 IPA。
- 使用时间列表优先显示名称；名称字符串不可用时通过系统 `Label(ApplicationToken)` 展示。App token 仅保存在本地，不上传 CSV；名称仅用于 App 内展示，不写入 CSV。

当前处于开发阶段，以当前数据结构为准，不维护旧数据兼容或迁移逻辑。需要调整数据结构时，可清空开发数据后重新采集。

## 组网管理

首页「组网管理」通过 Headplane 的 API Key 登录管理 Headscale，提供设备、网络、访问控制和更多四个原型页面。支持设备操作、路由审批、HuJSON 策略编辑、接入密钥创建/过期，以及用户、DNS 和 Agent 只读查看。接入密钥支持用户归属或纯标签模式、自定义整数有效天数。设备详情提供 App 内官方 Web SSH 终端，独立使用 OIDC 登录，要求服务端 Agent、目标 Tailscale SSH 及访问策略支持。连接凭据独立保存在支持 iCloud 同步的系统钥匙串；未知写入结果必须刷新核对后才能继续操作。

已核对 v0.6.2、v0.7.0、v0.8.0 和 v0.8.2 发布标签的 Headplane 页面数据协议，并通过 v0.8.2 本地契约测试，尚不保证开发分支兼容。配置、能力限制及验证方法见 [Headplane 组网管理](../../docs/headplane.md)。

首页「路由器」按概览、设备、网络、工具四页管理 TP-LINK 路由器。根据主应用返回的内网状态自动选择直连或 Sora 代理；外网访问需在主应用设置中选择家中在线的代理 Agent。支持在线/离线/禁用设备、搜索、绑定增删改、设备重命名与限速、主/访客 Wi-Fi、无线定时、UPnP、端口转发、唤醒、自动清理及系统日志。高级网络与复杂规则先提供只读查看；密码保存在独立钥匙串。原生客户端已在 TL-XDR5480 易展 Turbo 版通过登录、核心设备查询和 19 项只读资源验证，配置写入通过模拟协议测试，尚未执行真实设备写入验证。协议与范围见 [路由器子应用](../../docs/router.md)。

## 应用日志

首页 → 工具 → 日志，可查看 Hako、云服务器、容器管理、设备监控和使用时间的本机运行日志。支持按子应用、级别和关键词筛选，查看详情、选择文本、分享当前筛选结果或单条日志，以及清空全部日志。前台打开日志页时自动更新。

日志保留最近 1,000 条，普通事件按条限制长度，本机保存，默认排除备份，可在“iCloud 与换机恢复”中开启系统备份；不上传到 Hako 服务端。日志记录主要 API 请求的结果与耗时、终端连接状态及使用时间采集 / 同步结果，不汇集远端容器 stdout 或服务器系统日志。Headplane 的 HTTP 4xx / 5xx 和传输失败使用 error 级别，完整保留请求方法、地址、请求头和正文，以及响应状态、响应头和原始正文，不截断错误详情；传输失败标明未收到响应。API Key、认证头和 Cookie 脱敏，终端命令与输出不记录。连接 URL 的用户名、密码、片段和全部查询参数值均隐藏。

排查阿里云终端地址问题：点击终端「连接」后，返回首页 → 日志，筛选「云服务器」，打开「阿里云返回终端连接地址」。该事件在地址校验前记录，保留实际域名、显式端口和路径；会话 ID、Token 和 AccessKey 不写入日志。终端原样使用阿里云 `StartTerminalSession` 接口返回的 URL，不按地域拼接域名或限定固定域名格式；只检查地址包含主机、合法端口，使用 `wss` 协议且不含用户名密码。用于连接的域名、端口、路径和查询参数均不改写。

日志存储 / 脱敏 / 并发与保留上限测试位于 `Tests/HakoLogTests.swift`，阿里云拒绝地址仍记录日志并清理会话的回归测试位于 `Tests/ECSTests.swift`；均接入 GitHub Actions 的 Swift 验证步骤。

## 运动记录

主页的「运动记录」是独立子应用，支持手动新增、查看详情、编辑和确认删除。同一天可有多条记录，日期显示为 `yyyyMMdd`；类型使用英文，预设为 `Swimming`、`Biking`、`Hiking`、`Walking`，从 GitHub 导入的其他英文类型也会保留。距离单位为 km，时长为正整数分钟，无距离运动填 0。

运动界面沿用已确认的原型：标题旁提供「记录运动」，下划线标签与紧凑年份筛选独立排布；四项指标横排（辅助功能大字号时调整为两列），图表标题和单位置于卡片内，使用低饱和度类型配色和左侧纵轴。列表、详情与编辑表单沿用相同卡片样式。

概览展示运动次数、距离、时长、天数，以及每月次数和时长图。趋势页展示次数、时长、距离的月度及年内累计图，均按类型区分；图表点击月份或年份后，仅在图内显示定位线并高亮所选柱形或数据点；具体合计和各运动类型数值显示在图表下方的自适应数据面板，不覆盖柱线。再次点击同一位置或点击「收起」可关闭面板。月份和年份使用分类坐标，确保柱形有实际宽度。概览和趋势图表均可选择「总体 · 全部年份」：指标统计全部记录，图表改为按年汇总，累计值从最早记录年份起连续计算。选择具体年份时按月统计且累计值从该年一月重新计算。记录列表保持按年和月筛选。

运动模块沿用主应用的 GitHub 仓库、分支与 Token，不设置独立配置或手动同步按钮。数据按年保存至 `data/sports/<年份>.csv`，表头为 `id,date,type,distance_km,duration_minutes`。`id` 为 UUID，编辑日期或类型不改变 ID；页面不显示内部 ID。新模块不预填演示记录。

每次从 Hako 主页进入运动模块，自动拉取所有年度记录，以远端快照为基础；本地新增、修改和删除操作的时间晚于对应年度 CSV 最后提交时间时保留，否则以 GitHub 为准（相同时间也以 GitHub 为准）。删除通过本地操作日志保留标记，不能因拉取而无条件恢复。跨年编辑同时比较涉及文件的提交时间，并在一次提交中更新两个年度文件。仓库其他文件的提交不影响判断。

合并后自动上传保留的本地变更，无变更时只刷新。保存和删除先持久化在本地，下一次进入模块时同步。GitHub 分支发生并发变动时，重新读取并按相同规则合并，最多尝试三次；网络请求结果不确定时不自动重复提交。同步失败显示页面内错误，保留本地数据和待同步操作；上传失败仍保留已成功读取的远端数据。已确认成功的提交才清除操作日志。未配置 GitHub 时仍可记录运动，之后配置好主应用 GitHub 再进入即可同步。

本地运动数据及操作日志按仓库和分支隔离，采用原子写入；损坏数据不会被空记录覆盖。进入详情、编辑后返回运动列表不会重复触发入口同步。

代码边界：主应用只负责应用入口、导航注册、全局设置与通用服务。`AppServices.gitHub()` 向子应用提供 `GitHubRepositoryAccess` 接口：读取目录快照、读取指定快照的文本文件及其最后提交时间、基于预期 HEAD 批量提交文件，并报告并发更新。`GitHubService.swift` 内部管理配置、Token、GraphQL 请求与响应、路径校验和提交签名验证；这些实现及凭据不向子应用暴露。子应用通过接口注入访问 GitHub，不读取主应用的配置或 Token，不创建网络客户端、不构造 GraphQL 请求、不扩展具体传输类。`CSV.swift` 只做通用编解码。

`Sports/` 独立负责运动数据、校验、合并、统计、持久化与界面；`Usage/` 独立负责屏幕时间页面、数据模型、数据库、采集、同步回调、CSV 合并和 GitHub 业务适配。年度文件命名、模块目录和冲突策略均由子应用决定，主应用服务不识别运动或屏幕时间业务类型。使用时间的数据库在进入子应用或执行同步回调时按需初始化，损坏或打不开不会阻塞首页和其他子应用。模型类及默认数据库位置保持不变，以保留已有记录。两个子应用不互相引用业务代码。

子应用间复用的界面组件统一放在 `Shared/UI/`：`AssistantHTML` 与 `AssistantReplyView` 负责助手回复解析和展示，`ConversationScrollFollowing` 负责对话滚动跟随，`HakoCodeEditor`、`HakoCodeSyntax` 与 `HakoEditorLines` 负责代码编辑、语法高亮和行号，`HakoLabeledValue` 负责标签值展示。子应用直接使用共享组件，不引用其他子应用的类型；`Tests/test_subapp_boundaries.py` 检查子应用间类型引用及共享 UI 对业务类型的依赖。`Features/ServerManagement` 与 `Features/Notifications` 为主应用的登录管理和通知界面。

记账助手与青龙助手还共用 `Shared/Infrastructure/Assistant*` 的流式回复状态、输入草稿、会话文件保存和工具调用生命周期，以及 `Shared/UI/Assistant*` 的输入栏、消息图片、思考折叠、图片导入预览和调用详情。业务模块提供调用名称、参数摘要、结果解释与凭据隐藏规则，并保留各自的模型上下文、工具权限、表单和提交校验。提取共享代码不改变会话、草稿或调用记录的文件路径与保存字段；两套助手测试使用重构前生成的模拟文件检查读写格式。

大模型设置内置六家服务商的常用模型，可选择速度和推理强度，官方接口只需填写 Token。OpenAI 模型使用 Responses 协议接收工具调用，自定义 Chat Completions 与 Messages 接口仍保留。预设能力、续接规则与验证见[大模型预设与协议](../../docs/language-model-presets.md)。

子应用通知通过 `Shared/HakoServer/ApplicationNotificationRegistry.swift` 注册状态查询和预览页面回调。`HakoApplications` 统一调用子应用的注册入口，注册过程不创建业务运行实例；主应用通过共享接口查询当前页面、呈现预览，并在预览关闭后执行导航。代码工坊的会话匹配、运行状态和预览加载保留在子应用内部，主应用不直接访问 `WorkshopRuntime` 或创建工坊预览页面。边界检查仅允许应用清单引用子应用入口，其余主应用和共享代码不能引用子应用实现类型。

首页导航和快捷指令共用 `HakoApplications` 子应用清单。快捷指令首次运行时，清单调用子应用的注册入口，无需打开首页。使用时间和加密资产各自注册同步回调，主应用依次运行并汇总结果。各子任务独立拥有取消状态，单项失败或取消后继续执行其余子任务，包括后续投资备份，最终汇总各项结果并标记未完成项；只有整次同步被用户或系统取消时，才取消当前子任务并停止后续执行。手动重试只处理未完成项，不重复成功的备份。

「同步 Hako 数据」使用 iOS 27 的长时间后台执行机制，并按真实子任务和阶段上报进度；系统仍可因运行限制或用户操作取消任务。历史记录区分系统超时、用户取消和网络请求取消。失败、已取消和已中断的记录均可手动重试，只重新执行未完成的子任务，保留已成功和已跳过的结果。投资账本同步必须先完成本次服务端读取，读取失败时不使用旧缓存继续结算。

执行详情以结果摘要和关键业务步骤为主，每步显示实际结果和简短耗时；展开步骤查看起止时间与完整详情。设备身份、签名、登录会话和 HTTP 请求收进默认折叠的诊断信息，分享日志也按关键步骤与诊断信息分组。已保存的旧日志按同次执行中的完整阶段名称配对展示，不改写原始记录；同名并发阶段无法确定对应关系时保持独立，未曾记录的业务步骤不补造。

加密资产快捷任务先重新采集已配置的 HTX、Binance 和链上钱包，保存本机快照并补齐合约缺失字段，再合并并上传 GitHub 的资产汇总与 HTX TRX 合约年度 CSV；快捷任务不因余额缓存尚未过期而跳过采集。采集不完整或未配置来源时停止本项上传并报告原因，保留成功读取的数据和已有完整快照；上传失败保留待同步记录。加密资产页面的同步按钮仍只上传本机缓存。日志记录各来源采集、快照保存、归档合并数量、文件提交或无需提交，以及同步状态保存。使用时间记录授权、最近七天补采结果及各年度同步结果；投资定投和快照、备份步骤附带实际业务结果。

Binance 页面提供「资产 / 图表」切换。Funding 中 `EQ` 开头的股票单列为 Stock，从 Funding 分类金额中扣除，原始交易所快照与总资产不变；未提供股票报价时不把金额当作零。资产趋势展示资产总额曲线，支持常用范围与自定义起止日期，使用每日 Binance 余额并保留缺失日期断点。资产分布按最新持仓快照展示，包含小额资产；点击扇区或行内容切换高亮，只有独立的右侧箭头进入分类内资产占比，可返回全部资产。分布显示每项资产的分类内占比和 Binance 总资产占比，缺失估值或负值时不绘制误导性的饼图。日期范围仅用于趋势，不以最新持仓伪造历史分布。

主应用「设置」一级页面并列提供「快捷指令」与「快捷指令执行历史」入口。「快捷指令」二级页面先展示实际注册的完整子任务清单，尚未执行时也可查看；点击「立即同步 Hako 数据」执行全部子任务，页面持续显示各子任务状态、当前处理阶段、完成数和最近一次结果。与系统快捷指令共用长时间后台执行、取消和历史记录流程；执行中禁止重复启动。此入口按手动模式执行，投资备份不受星期限制，系统快捷指令入口仍按周日规则判断。历史列表和详情显示首次触发来源，并单独保留最近重试来源；子任务每次尝试也记录来源。来源只区分「App 内触发」与「快捷指令触发」。此前没有记录来源的执行显示「未记录」。

「设置 → 快捷指令执行历史 → 执行详情 → 子任务」可查看执行结果及带时间的阶段日志，并通过右上角分享日志。投资账本记录账本读取、行情和定投处理、历史行情补充、快照保存，以及认证中的设备身份读取、Secure Enclave 公钥／签名、登录会话读取／保存／刷新和 HTTP 状态；安全存储错误保留实际 OSStatus 和操作对象类别。每个子任务最多保留最近 200 条日志，重试保留先前日志，迟到的旧任务日志不会混入新尝试。日志记录应用状态和受保护数据可用性，隐藏凭据，不记录请求正文、Token 或密钥内容；旧记录没有详细日志时需重新执行生成。

主应用通过 `AuthenticatedServerAccess` 提供登录状态、会话上下文、变更通知及已认证请求，`ConsoleClient` 仅实现身份与会话管理。设备监控的 `DeviceMonitorClient`、ECS 访问统计的 `ECSAccessAPI` 均注入该接口，不引用或扩展主应用具体客户端。业务路径、参数、解析和错误翻译留在各自子应用。缓存按服务器、账号和会话隔离，切换身份后的旧请求结果被丢弃。日志来源由调用方传入，主应用不解析子应用 URL。

主应用的 `SecureStorage` 提供按 service 命名空间隔离的 `SecretStorage` 接口，统一负责 Keychain 读写、删除和账号枚举。原有 service/account 和 JSON 格式保持不变。GitHub、交易所、行情、模型、SSH 与各面板连接等明确列入同步范围的凭据使用 iCloud 钥匙串；保留各项原有的解锁时／首次解锁后访问时机，移除其设备限定。Console 设备身份和服务端会话继续使用 ThisDeviceOnly。旧本机凭据先成功写入同步项再清理旧副本，云端已有同名项时不覆盖，准备失败保留本机原值；删除会同时清理云端与遗留本机项。子应用保留自身凭据模型、校验、编码和错误提示，可注入内存存储验证业务，无需访问真实 Keychain。

`HTTPTransport` 统一创建无 Cookie、缓存和自动凭据存储的临时网络会话，并拒绝重定向，避免凭据被转发。Arcane 保留较长操作超时；主应用服务器、GitHub 和 ECS 共用同一基础策略。阿里云签名、Arcane API 与终端协议仍由各子应用实现。客户端只负责释放自己创建的会话，不关闭外部注入的会话。`Tests/test_subapp_boundaries.py` 检查上述依赖边界及 CI 源文件路径；`CredentialStorageTests.swift` 验证凭据适配器的校验、规范化和失败时保留数据。

运动核心和模拟 GitHub 测试分别位于 `Tests/SportsTests.swift`、`Tests/SportsGitHubTests.swift`，已接入 iOS CI；两项测试仅依赖主应用通用层和运动模块，不依赖屏幕时间的数据模型。

`Tests/SportsRepositoryTests.swift` 仅链接主应用接口和运动业务代码，使用内存假服务测试，无需链接 GitHub 配置、Token 存储或具体网络实现；架构检查会阻止子应用重新直接访问凭据或具体传输类。

## 首先确认 Apple 的数据访问授权

普通 `DeviceActivityReport` 被沙箱限制，不能把敏感使用时间写出报表扩展。此项目使用 iOS 26.4 的 `DeviceActivityData.activityData(filteredBy:using:)` 官方导出 API。

需要 `com.apple.developer.family-controls` 和 `com.apple.developer.family-controls.app-and-website-usage`，并取得 `approvedWithDataAccess`。工程已声明 entitlement，但声明不等于 Apple 已授予签名权限。付费开发者账号、不上架或个人侧载均不自动保证该权限可用。

Apple 文档说明：开发测试可以使用 Apple 提供的 provisioning profile 在任意地区进行；客户安装要求设备位于欧盟且 Apple Account 地区为欧盟。必须用自己的开发者 Team 和支持该能力的 provisioning profile 真机验证。若无法取得该权限，当前全自动方案不能运行，需另行选择截图识别或手动录入方案；本版本不会假装采集成功。

## 第三方应用管理

主应用「设置 → Hako 服务 → 第三方应用」以原生分组列表打开，使用当前已登记 Console 的登录身份管理服务器上的应用，与 Web 管理页共用记录。未登录时提供「服务器与登录」入口；列表支持下拉刷新及右上角加号登记。

登记填写应用名称与登记来源，默认支持自定义扫码协议。OIDC 须单独启用，登记精确 HTTPS 回调地址，选择是否提供 profile、要求 PKCE S256 及 Secret 认证方式。详情可复制不含 Secret 的接入信息、修改 OIDC 配置、启停应用或轮换 Secret；停用、轮换和修改 OIDC 前均明确提示授权失效。

创建或轮换成功后打开一次性凭据页，Secret 默认隐藏，可显示和复制完整接入配置；关闭前确认已保存。Secret 仅保留在当前页面内存，不写入 UserDefaults、Keychain 或日志，关闭或切换服务器/账号/会话后不再显示。复制的秘密配置仅写入本机剪贴板，不通过通用剪贴板同步。失去响应时先刷新核对，不自动重复创建或轮换；原始 Secret 遗失须轮换。

需同步部署支持 `/api/v1/applications` 的服务端。接口使用现有 Console DPoP，不使用管理网页 Cookie 或第三方应用 Secret。详见[认证协议](../../docs/server-authentication.md)与 [OIDC 接入](../../docs/server-oidc.md)。

## 安装及配置

「设备监控」主页进入时验证会话并更新设备列表，此后每 10 秒自动刷新设备及在线状态，不显示刷新按钮或 loading 行；离开主页、打开添加 Agent 或服务器配置 sheet，或 App 进入后台时停止轮询，返回前台主页后恢复。主页「添加 Agent」下一行保留共享的「服务器与登录」快捷入口，未配置或未登录时也可进入；扫码入口统一位于 Hako 主应用设置页。列表和详情均支持下拉刷新，保留系统原生反馈。设备监控设置的「页面排序」标题下显示当前设备的 ID 和名称。刷新时保留已有数据，失败时显示错误提示。详情直接调用一次 `query.all` 获取查询数据，不再先请求设备列表。进入详情时自动执行同样的查询，离线或不支持的动作由服务端返回提示，不使用列表中的旧状态阻止刷新；设备重新上线后可直接在详情刷新，无需返回列表。

设备列表中的离线设备保留名称、设备 ID 和离线状态，禁用详情入口；列表刷新为在线后恢复进入详情。已进入详情后断线仍保留当前页面及刷新能力。

Hako 主应用冷启动及返回前台时自动验证已保存的登录凭据，不加载设备列表；进入设备监控后验证会话并单独加载设备。页面显示状态或前后台状态变化引发任务重启时，后续调用复用正在进行的验证，请求不会随原页面任务取消。验证期间显示静态状态说明，不显示 loading 动画；正常的网络请求取消不作为错误展示。真实网络故障保留凭据和错误提示，由主页后续轮询或手动操作重试，仍需服务端验证成功才进入已登录状态。

登录 Hako 服务器后，点击「添加 Agent」，只需填写设备名称，粘贴或从文件导入 Agent 导出的 PEM 公钥。确认表单中的服务器和账号后点击「添加」，服务端自动生成 5 位设备 ID（大写字母和数字，以字母开头，例如 `A7K2Q`），公钥立即登记并刷新设备列表，无需打开网页或重启服务端；在对应设备的 Agent 中重新连接即可上线。名称最多 100 个 UTF-8 字节，公钥需为 RSA 2048–8192 位。私钥会在本地阻止提交；重复公钥及其他错误保留表单供修改。网络失败时先刷新设备列表确认是否已登记，避免重复提交。此功能需要同步更新服务端；iOS 本机 Console 公钥仍需事先在服务端文件登记。

主应用公钥入口为「设置 → 服务器与登录 → 本机设备身份 → 查看与导出公钥」。打开 sheet 后显示完整 PEM 公钥和设备 ID，可选中文本、复制公钥内容或导出 `iphone.public.pem` 文件。无需填写服务器地址、账号，也无需联网或登录；首次自动生成并保存本机 Secure Enclave 密钥，重复导出复用已有身份。之后填写连接信息并点击 sheet 右上角勾号保存，新服务器使用已准备的设备身份。升级后保留已有服务器绑定的密钥，不重新生成。

已有密钥时，同一区域显示独立的红色「重置密钥对」入口，打开专用确认 sheet，仅显示重置说明、确认和取消；公钥查看 sheet 不包含重置操作，重置 sheet 不包含公钥复制或导出。再次点击红色「确认重置密钥对」才会生成并保存新密钥，退出本机 Hako 服务器登录并清理旧身份和会话凭据；取消或关闭不会重置。重置成功后返回设置，可再打开「查看与导出公钥」获取新公钥。旧密钥不可恢复。重置可离线完成，之后需重新导出公钥，手工替换服务端旧公钥并重启，才能重新登录；服务端及关联网页会话会在旧公钥移除并重启后失效。生成、导出校验或保存失败时保留原密钥。新身份的保存与重置标记一同提交，清理中断也不会让旧服务器绑定恢复旧密钥。

1. 打开 `Hako.xcodeproj`，选择 Hako target → Signing & Capabilities → 自己的付费开发者 Team。使用匹配上述两个 entitlement 的开发描述文件。若签名报错，先解决开发者后台权限/profile，不能简单删除 entitlement 后宣称可导出。

## iCloud 与换机恢复

设置中的「iCloud 与换机恢复」区分三种机制：密钥与连接配置由系统 iCloud 钥匙串同步；普通设置通过 iCloud key-value store 同步；提示词、快捷提示词、助手会话和未发送草稿纳入系统整机备份。文件恢复需要在新手机设置过程中恢复包含 Hako 的整机备份，不提供文件实时同步，也不会把“已允许备份”显示为“备份成功”。需在系统中开启 iCloud 密码与钥匙串、iCloud 云备份，并确认备份包含 Hako。

普通设置使用明确白名单，包括主题、首页排序、GitHub 仓库、服务器地址及用户名、网络环境与工坊地址、观察钱包、自选币种和投资显示偏好。按安装实例分别保存低优先级种子和修改项，避免旧本机设置覆盖尚未下载的其他设备修改；后续按修改时间协调云端与离线修改，并记录删除；不上传设备身份、登录会话、执行中状态、缓存或任意 UserDefaults。iCloud 账户变更时暂停设置同步，需确认新账户后重新开启。部分连接配置下次启动生效，系统同步时延及其他设备是否接收无法由本机确认。

执行历史与运行日志默认不备份，可通过单独开关纳入整机备份。工坊草稿与消息缓存虽然共用目录，但逐文件区分备份：目录允许备份，草稿及提示词保留，消息和目录缓存排除；更新时修正已有文件标记。投资账本和已上传的 GitHub 历史仍沿用原服务恢复，新手机的 Secure Enclave 设备身份需要重新登记和登录。

回归测试 `CloudRecoveryPolicyTests.swift` 验证首次下载、离线修改、删除传播、类型白名单及备份范围；`CloudKeychainTests.swift` 使用内存 Security 适配器验证同步访问级别、迁移失败保留数据、云端值优先、删除不复活旧值和设备身份隔离。真实 iCloud 钥匙串同步、双设备设置接收和整机备份恢复仍需同一 Apple 账户真机验收。

## 金融 API Token

主应用「设置 → 金融 API Token」统一管理投资记账和加密资产的凭据，显示字段的稳定 key、配置状态和使用子应用。A 股选股通过 Hako 登录，无手填 API Token；其声明的凭据列表为空。非金融模块的配置与快捷指令不受此功能影响。

金融子应用在自己的 `HakoApplicationModule.credentials` 中声明凭据名称、字段 key、字段名称与验证器 ID，不再提供凭据 JSON 文件。例如：

```swift
credentials: [
    .init(title: "Tushare Pro",
          fields: [.init(key: "tushare.token", title: "API Token")],
          validatorID: TushareCredentialValidator.identifier)
]
```

主应用从统一模块清单收集声明，在创建子应用页面前同步配置 `HakoTokens`。声明只包含元数据，禁止放入真实 Token 值。声明合并与合法性检查不访问钥匙串；调用原有读取或保存接口时才访问存储。

子应用通过 `try HakoTokens.read("tushare.token")` 读取。相同的 key 共用凭据，并合并子应用关联；Twelve Data 的 `twelve-data.api-key` 已由投资记账和加密资产共同声明。Key 只能包含字母、数字、点、下划线和连字符，首字符为字母；同一凭据组的完整 key 集合必须一致，不允许同一个 key 同时属于不同分组。HTX 和 Binance 的 API Key、Secret Key 分别归入同一组，一起保存或清空，禁止只更新一半。

所有凭据值保存在主应用的系统钥匙串命名空间 `me.stackli.hako.financial-tokens`，同一条记录同时保存整组值、字段名、子应用 ID 和显示名称；按现有 iCloud 钥匙串策略同步。原子保存以整组记录为单位，子应用仅显示配置状态，密钥的编辑、清除和验证统一放在主应用。投资接口详情保留调用统计。

金融旧凭据导入已在 0.9.44 完成真机确认，后续版本已移除旧存储读取、迁移映射和前台迁移触发。主应用只读取已持久化的钥匙串记录；模块声明、key、凭据分组和子应用关联继续使用。由 JSON 改为 Swift 声明不改变钥匙串命名空间、分组 ID、字段、关联顺序或 v1 记录格式，无需迁移或重新录入。已有记录的存储命名空间及 v1 数据格式保持不变，历史来源字段仅作为存储元数据保留。清空仍会保存空记录及关联，不删除用户的旧存储数据。

## 子应用统一注册与密钥验证

`HakoApplications.modules` 是唯一的子应用入口清单。每个子应用在自己的 `*ApplicationModule.swift` 中提供 `HakoApplicationModule`，集中声明分类、说明、图标、页面工厂，以及快捷指令、通知、固定页面、备份范围、主应用设置和密钥验证器的注册回调。HTTP 代理和通知管理作为没有首页页面的入口注册主应用设置。页面和业务回调按需执行，注册入口本身不读取数据库、不发起网络请求。

新增子应用时添加稳定的 `Application` 导航标识及一条模块入口；已有子应用新增能力只修改自己的入口及实现，不再向主应用增加按能力分派的 `switch`。原有导航标识、分类持久化 key 和默认顺序保持不变。注册清单会检查重复或遗漏的页面入口。

金融子应用模块的每个凭据组必须声明 `validatorID`，例如 `TushareCredentialValidator.identifier`。同名 key 的共享声明必须归属于同一完整凭据组、使用同一个验证器 ID。子应用实现 `HakoCredentialValidator`，声明标识、完整 key 集合和异步验证方法，再从自己的模块入口调用 `registration.credentialValidators.register(...)`。主应用只把该组的已保存凭据传给对应回调，不把其他密钥传入；HTX 与 Binance 始终整组验证。

主应用的密钥编辑页保存后保留当前页面，提供“验证已保存的凭据”。有未保存修改时禁用验证；验证可取消，离开页面会取消当前任务。结果区分验证通过、鉴权失败、权限不足、限流和暂时无法确认。验证开始及结束都会核对已保存值，期间凭据变更会丢弃旧结果。结果和时间仅在当前设置会话展示；修改密钥后清除旧结果。凭据组的钥匙串命名空间和 v1 存储格式不变，验证器 ID 来自子应用模块，不复制进凭据值。

验证只调用只读接口，不写入业务数据：Tushare 读取前一天交易日历；Twelve Data 查询密钥用量；HTX 使用签名读取账户列表；Binance 使用签名查询 API Key 权限；Moralis 对公共零地址读取 EVM 代币列表。响应正文不记入验证日志，错误结果隐藏原始密钥；网络失败不会被当成密钥无效。

TRONSCAN 的公开区块接口可能对无效密钥仍返回数据，因此额外以同格式的变造密钥做一次只读对照。只有当前密钥成功、对照明确遭到鉴权拒绝时才标记通过；两者均成功或对照无法完成时，显示“暂未验证通过”，不把可访问误报为鉴权有效。

接口依据：[HTX 只读账户接口](https://huobiapi.github.io/docs/spot/v1/en/)、[Binance API Key 权限](https://developers.binance.com/en/docs/catalog/core-trading-wallet/api/rest-api/account)、[TRONSCAN API Key 限制说明](https://docs.tronscan.org/en/api/api-keys)、[Moralis API 鉴权](https://moralis.readme.io/reference/introduction)。单项检测通过仅代表该检测接口的权限和鉴权正常，不代表服务商所有接口均可使用。

## 子应用图标

13 个首页子应用在自己的 `HakoApplicationModule` 入口声明 `icon: .asset("InvestmentIcon")`，无需图标 JSON 或 `metadataID`。图标 SVG 源文件保存在各自 `<Feature>Assets.xcassets/<Asset>.imageset/`。修改图形后运行 `python scripts/render-application-icons.py --renderer rsvg-convert`，将透明 PNG 更新到子应用的 `Icons/<Asset>Template@3x.png` 并一同提交。共享渲染器直接读取 PNG 文件，避免资源目录编译产生的不透明模板遮罩；不再从 `Assets.car` 加载这些首页图标。

图标统一采用 32×32 画布、2 单位线宽、圆端点和圆连接，不包含背景。主应用统一按模板渲染，继承动态前景色，适配浅色和深色模式。

PNG 使用 96×96 像素的 3x 透明底图，包含源 SVG 的 SHA-256。验证检查图形覆盖率、透明像素、边缘和源文件指纹，避免只检查 SVG 结构却未发现运行时图片是实心方块。打包后应核对 13 个 PNG 已作为独立资源包含在 App 根目录。

首页、子应用排序、应用通知及固定页面的默认应用图标统一使用 `HakoApplicationIcon`。青龙没有独立加载分支；未声明或资源缺失时显示统一占位图标。子应用自行提供的固定页面专用图标仍由原回调呈现。

## 卡顿与崩溃诊断

设置中的「卡顿诊断」收集三类异常：前台主线程响应超过 2 秒、弹层切换就绪或动画回调超过 10 秒、MetricKit 下发的系统卡顿及崩溃报告。主线程检测由独立后台队列发起单个探测，阻塞期间先落盘，恢复后更新同一条记录；离开活跃前台后停止计时，不将锁屏或后台停留算作卡顿。主队列探测不采集调用栈，不将其工作线程的栈冒充为主线程栈；系统报告保留系统提供的调用栈和报告区间，接收时间不冒充故障发生时间。

诊断报告与普通滚动运行日志分开保存于应用支持目录 `HakoLogs/Diagnostics`，按最近 100 条及报告总计 8 MiB 淘汰较早记录，单条正文最多 512 KiB；普通日志清理不会删除诊断。系统报告按内容指纹持久化去重。操作轨迹另保留最近 100 条，记录前后台、快捷访问、通知跳转、弹层开始/完成/超时和未保存保护状态，只包含控制器类型及状态，不记录会话正文、页面标题、通知正文、URL 或凭据值。轨迹在重启后可查看；系统报告关联的当前进程轨迹不能证明是同一次故障。诊断页支持复制、分享和独立清理；没有记录不保证没有问题，系统终止报告仍取决于 iOS 是否提供。
