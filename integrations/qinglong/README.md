# 青龙：Hako 行情同步

将同目录 `hako_market_sync.py` 上传到青龙「脚本管理」。脚本只依赖 Python 3.10+ 标准库；容器需安装系统时区数据库 `tzdata`，供 ECB 发布时间换算使用。不要将密钥写在脚本中。

## 配置

Hako 服务端需要先部署 **0.9.0 或更新的 0.9.x 版本**。在 Hako「第三方应用」登记一个供青龙使用的应用，开启「读取行情更新清单」和「写入行情与汇率」两项权限；不需要开启扫码、原生或 OIDC 登录。登记来源填写青龙的实际地址。

标的和行情全局共享后，采集流程保持不变：脚本直接使用清单返回的 `instrumentId` 和 `targetId`，不解析 ID、不生成数据库主键。`STOCK`、`ETF`、`FUND` 等大写类型前缀及统一的 `US` 市场均可直接使用；每轮重新获取目标签名，升级前的旧目标不要手工重用。环境变量、AK/SK 和任务命令无需调整。

在青龙「环境变量」添加以下变量，每个名称只配置一个启用值：

| 变量 | 内容 |
| --- | --- |
| `HAKO_URL` | Hako 的 HTTPS 根地址，例如 `https://hako.example.com`；不要填写青龙地址或 `/api/v1` |
| `HAKO_CLIENT_ID` | Hako 第三方应用 AK，即 `app_...` 应用 ID |
| `HAKO_CLIENT_SECRET` | 同一 Hako 应用的 SK；这些不是青龙开放平台的 Client ID/Secret |
| `TWELVE_DATA_API_KEY` | 有美股或美股 ETF 时填写；没有美股则可不填 |

Hako 不会将手机中保存的行情商凭据返回给脚本；美股需要在青龙另配有效的 Twelve Data Key 和相应行情权限。

建议先手动执行：

```sh
python3 /ql/data/scripts/hako_market_sync.py --check
```

该模式只验证 Hako 读取权限和待更新清单，不访问行情源，也不验证写入权限。再用 `--dry-run` 实际采集但不写入；验证无误后移除参数正式运行。

青龙任务命令（若上传到子目录，请相应调整路径）：

```sh
task hako_market_sync.py
```

五分钟执行一次的青龙六段 Cron：

```text
0 */5 * * * *
```

脚本头也包含此定时信息，供订阅识别。Cron 由面板时区解释；行情日期转换与该时区无关。运行超过五分钟时，下一次任务会因独占文件锁跳过，避免同一容器重复运行。

## 采集范围

| 数据 | 行情源及规则 |
| --- | --- |
| A 股、场内 ETF | 东方财富未复权日线；支持 `.SH`、`.SZ`、`.BJ` 或明确交易所 MIC |
| 港股 | 东方财富；明确 `HK_CONNECT`、`XHKG`、`HKEX`、`HK` 市场，五位代码 |
| 场外基金 | 天天基金历史单位净值，代码以 `.OF` 结尾；不把货币基金每万份收益当净值 |
| 国内期货 | 东方财富；支持 `.SHF`、`.DCE`、`.ZCE`、`.CFX`、`.INE`、`.GFE` 明确交割月份代码 |
| 美股、美股 ETF | Twelve Data；核对代码、币种、交易所，历史使用未复权日线；最新价使用实际报价时间 |
| Binance 加密资产 | Binance UTC 日线／现货，按用户确认的 1 USDT≈1 USD 直接估值；USDT 本身固定为 1 |
| 汇率 | ECB 日参考汇率，通过同日欧元交叉盘计算，不填充未发布日期 |

当前不采集期权、无法明确识别交易所的代码以及非美元计价的加密资产；遇到这些目标会明确记录失败，其他可采集目标继续执行。美元标的也须有明确美股或 Binance 交易所，不会仅凭币种将未知标的当成美股。东方财富和天天基金沿用 iOS 已有公开接口，接口变动、风控或访问地区限制可能导致失败。Twelve Data 受 Key 套餐权限限制，未配置时只影响美股目标。

国内最新价使用当日日线中已返回的价格。服务端 0.9.1 起，场外基金仅生成历史单位净值任务，不生成当天 `latest` 任务；新持仓／关注向前查询最多近 30 天以发现最新已公布净值。收盘前截止上个工作日，收盘后允许查询当天，但只保存实际已公布净值及其原始日期，不假定 T+1 或把旧净值改成今天。尚未公布的日期只冷却 15 分钟，然后允许重查，兼容 QDII 等延迟公布。美股休市时返回上个交易日的报价会跳过，不改成今天的日期。最新价刷新间隔实际还受 Hako 清单的五分钟新鲜度判断影响。

## 执行及失败处理

1. 分页读取 `/api/v1/market/update-targets`，不读取账户、金额或交易明细。
2. 对清单指定的标的和日期采集数据；已有历史记录默认复用。
3. 使用十进制计算，并**显式四舍五入至四位小数**以满足当前接口精度。舍入后为零的价格拒绝写入，并记录失败。
4. 向 `/api/v1/market/quote-batches` 上传。根据实际 JSON 字节数分包，每包小于 15,000 字节，适配服务端当前 16 KiB 正文上限。HTTP 200 仍检查每项 `status`。
5. 所有记录能在一个包内发送且行情源完整返回时，设置 `complete:true`。分包时各包均为 `false`，避免将其他分包中的日期误判为无数据；下一轮从服务端重新读取剩余缺口。
6. 成功写入后再从第一页查下一轮缺口，最多十轮。同一次运行不会反复处理相同的标的和日期区间。

没有数据只表示本次查询暂无已发布报价，不写零、不伪造历史。失败的提供商请求不会标记覆盖完成，失败任务返回非零退出码。不同目标互不影响；已成功写入的数据保留。没有待更新数据正常结束。

网络错误和 HTTP 5xx 每次最多请求三次。网络重试日志包含域名、尝试次数、耗时及 DNS／TLS／超时／对端断开等错误类别，不输出原始异常文本或完整 URL。东财同一域名连续三次网络请求失败后暂停该域名 60 秒，其余标的记为「延后」并留待后续执行；天天基金等不同域名继续处理。连接异常不会被标记为已查询或覆盖完成，已有行情保留。HTTP 429 遵守至少 60 秒冷却及更长的数字 Retry-After；同一请求重试使用相同正文和观察时间。业务限额错误会记录失败，不回显可能含密钥的响应正文。Hako 写入按同一标的、日期、类型、来源 upsert，相同数据重试不重复插入。目标 15 分钟有效，过期后停止该目标并留待下一次重新查询。

Hako 请求与提供商请求分别构造请求头，AK/SK 仅发送到配置的 Hako 地址。禁止重定向转发凭据；默认不使用环境 HTTP 代理。日志不输出完整 URL、请求头、响应正文、签名 targetId 或密钥。`--dry-run` 同样遵守这些规则。

可选环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HAKO_MARKET_TIMEOUT` | `25` | 单次请求超时秒数，5–60 |
| `HAKO_MARKET_MAX_SECONDS` | `600` | 一次运行总时间上限，30–3600；达到上限剩余任务留到下次 |
| `HAKO_MARKET_MAX_ROUNDS` | `10` | 清单补数轮数，1–100；每轮可多页 |
| `HAKO_MARKET_USE_PROXY` | 关闭 | 设为 `1` 才读取环境 HTTP/HTTPS 代理配置 |

Twelve Data 请求固定至少间隔八秒；Hako 至少间隔 0.6 秒；其他源串行采集并限制请求间隔。本脚本没有后台常驻进程，不保存密钥或另建行情数据库；任务重跑以 Hako 服务端清单为准。

运行离线测试：

```sh
python3 -m unittest discover -s integrations/qinglong/tests -v
```

接口协议见 [Hako 外部行情更新](../../docs/market-updates.md)。行情源协议参考 [Binance](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/market-data-endpoints)、[Twelve Data](https://twelvedata.com/docs/market-data/time-series)、[ECB](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)。
