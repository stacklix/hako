# Kage 用户文件管理

Hako 在 Kage 设备详情的「文件」页管理运行 Kage 的 Windows 用户主目录。服务端只做通用命令鉴权和透传，不解释文件路径、操作或结果。

顶部以一行小字显示根目录，目录导航和搜索、刷新、显示选项、新建按钮放在同一行。搜索按钮位于刷新左侧；关键词和结果均在独立 Sheet 内显示，搜索当前目录的名称，不递归扫描子目录。文件夹优先、名称排序，支持显示隐藏项目及分页。

点击文件打开文本编辑 Sheet，支持保存、只读状态和未保存草稿保护。Markdown 文件提供「预览 / 编辑」切换，预览当前草稿；渲染复用共享 Markdown 组件，禁用远程资源和脚本。新建文件先创建空文件，再打开编辑；重命名和删除在每项的菜单中，删除前必须确认，文件夹删除包含其内容且不可撤销。

## 协议 v1

| 命令 | 参数及结果 |
| --- | --- |
| `query.files.list` | `path`、`query`、`offset`、`showHidden`；返回根目录、相对目录、条目、下一页及不完整标记 |
| `query.files.read` | `path`、`offset`、可选 `revision`；返回大小、SHA-256、编码、可编辑状态和 Base64 数据块 |
| `query.files.operation` | UUID `requestId`；查询已提交修改操作的持久化回执 |
| `action.files.mutate` | UUID `requestId`、`operation`、`path`；新建另需 `name`，重命名另需 `name` 和条目 `revision`，删除需条目 `revision` |
| `action.files.write.begin` | UUID `requestId`、`path`、原文件 `revision`、草稿 `sha256`、`size`、`encoding` |
| `action.files.write.chunk` | 相同 `requestId`、`offset`、Base64 `data`；顺序上传，重复块必须一致 |
| `action.files.write.commit` | 相同 `requestId`；核对完整性、原文件版本后原子替换，并保存回执 |

文件查询按需执行，不加入 `query.all` 或实时订阅。`operation` 为 `createFile`、`createFolder`、`rename` 或 `delete`。路径均相对于固定用户根目录，不能传入任意根目录。文本最大 256 KB，每块最大 8192 字节；支持 UTF-8、UTF-8 BOM 和带 BOM 的 UTF-16，保存保留编码、文件创建时间、隐藏等属性和访问控制列表。二进制或过大文件只显示不支持预览的原因。

目录最多扫描 10,000 个项目，每页最多 100 项并受消息大小预算限制。递归删除预检查最多 10,000 个条目、64 层目录；存在受限链接或内容过多时拒绝。无法读取部分条目会标记列表不完整，不把遗漏描述为空目录。

所有祖先目录通过句柄固定，拒绝目录穿越、设备名称、备用数据流、符号链接、目录联接和多硬链接文件。叶子使用不跟随重解析点的已验证句柄操作；禁止改动用户根目录和活动文件操作记录目录。条目变更后不能使用旧版本重命名或删除；保存时再次核对完整文件摘要，冲突保留手机草稿。

修改在执行前持久化请求编号，相同编号和内容不会重复执行。回执状态为 `completed`、`failed` 或 `unknown`；重启后未完成的记录返回 `unknown`，不自动重放。网络故障时 Hako 保存待核对编号并暂停新修改，允许查询原回执、刷新目录核对；使用者手动确认实际文件后可结束等待。失败或取消的递归删除可能已删除部分内容，须刷新核对。记录达到 4096 项时拒绝新修改，由使用者在电脑整理记录，不静默丢弃去重记录。

## 验证

Windows 检查程序的 `user-files` 模式使用隔离目录验证增删改查、分块保存、编码、访问控制、冲突、去重、重启恢复、目录固定、联接及硬链接边界，不修改真实用户文件。`DeviceFilesTests.swift` 验证 iOS 路径、条目、分页、回执和编码模型。
