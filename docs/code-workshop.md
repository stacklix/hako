# 代码工坊

代码工坊通过 Windows 应用中的独立工坊服务使用本机 Codex CLI App Server。它拥有独立的 hako.workshop/1 协议、WebSocket 连接、请求池和在线状态，不借用设备监控协议或 Agent 连接。账号登录和已登记的电脑公钥仍由 Hako 主应用管理。电脑需要在当前 Windows 用户下安装并登录 Codex CLI。

当前按 Codex CLI 0.164.0 的本机协议验证。含后台任务通知的工坊需要服务端 0.2.1、Windows 1.1.1 和 iOS 0.2.1，三端需协同升级，不回退到设备监控通道。

代码工坊支持最新消息摘要、进行中标记和未读标记。列表从实际消息记录倒序读取最新的用户或助手文本，跳过工具和空文本，包含同一轮内追加的消息；轮次摘要仅用于状态和完成标记。列表先显示有未发送文字或图片草稿的会话，其次显示处理中或未读的会话，最后显示已读会话。处理中和未读属于同一优先级；每一组都按最近一次用户消息成功发送的时间倒序排列，同一秒使用会话 ID 稳定排序。清空或发送草稿、任务结束、标为已读或未读过期后，重新归入对应组，不改写发送时间。普通消息、补充回答及排队消息均按电脑接收的时间计入；打开会话、工具执行、助手输出、排队消息开始执行和重试原请求不改变该时间。电脑先合并发送时间再分页，同一秒使用会话 ID 稳定排序。此排序需要 Windows Agent 1.2.7 和 iOS 0.5.1；列表的 `lastSentAt` 为 Unix 秒，原 `updatedAt` 继续用于状态新旧判断和未读过期，不作为排序依据。服务端继续原样转发工坊请求和结果。未读按电脑、会话及完成轮次在手机本地保存，最后更新超过 12 小时后不再显示标记；列表停留期间也会定时更新过期状态。会话位于前台、最新消息可见时清除未读，上滑阅读历史、查看弹出详情或切到后台时保留标记。

列表状态由最新轮次和 Agent 实际执行中的任务决定。线程本身的 `active` 标记不会覆盖最新轮次的完成、失败或中断结果；本机任务仍在等待确认或释放写锁时，继续显示实际任务状态。

会话行左滑露出橙色归档按钮，点击后归档，不支持整行滑到底直接执行。左上角会话数量菜单可切换已归档列表，再左滑取消归档。进行中、排队和暂停的会话不能归档，电脑离线或归档提交中禁用操作；列表右侧不再显示更多按钮。

## 会话与应用

会话中的 HTTP / HTTPS 链接（包括截图链接）在 iOS 工坊的内置浏览器 Sheet 中打开，支持后退、前进、刷新、停止加载和复制链接；新窗口链接也留在同一个浏览器中。关闭后返回原会话，保留草稿和阅读位置。浏览器使用独立的临时网页数据存储，不向网页注入 Hako 登录凭据或原生接口；非网页协议不从该入口拉起其他应用。浏览网页时暂停将底层会话计为正在阅读，避免清除新到消息的未读状态。行内代码的轻点复制行为保持不变。

### 系统提示词

在「代码工坊设置 → 系统提示词」编辑并保存，可恢复默认内容或留空。设置按服务器账号保存在手机本地，同一账号的所有项目共用，公网和局域网切换不影响它。编辑支持最多 4,000 个 UTF-16 代码单元。

仅新建会话的第一条 `turn.start` 请求携带 `systemPrompt`，Agent 在创建 Codex 线程时将其作为 `developerInstructions` 传入，保留 Codex 原有基础指令。提示词与首条请求一起持久化，原请求重试沿用同一份内容；不混入用户消息，也不作为聊天气泡展示。已有会话、排队消息、Steer 和后续轮次都不重新传入，沿用 Codex 线程创建时的提示词。修改设置只影响之后新建的会话。

默认提示词要求：每次原型新建或修改都使用全新、唯一的文件路径，并在当次最终回复中发送一张新的原型卡片，不能复用旧卡片路径或只说明“已修改”。此功能需 iOS 0.3.2 和 Windows Agent 1.2.2；服务端沿用 0.3.1 的既有请求转发，不增加接口或部署要求。

### 局域网直连

iOS 主应用「设置 → 网络 → 网络配置」统一管理内网 Wi-Fi 名称与子应用 IP、端口，目前支持代码工坊。原应用更新区域的网络检测与 Wi-Fi 配置移到此处，已登记的 Wi-Fi 自动保留。应用更新继续使用同一份内网判断。

主应用通过 `LocalNetworkProviding.endpoint(for:)` 提供地址：只有当前连接 Wi-Fi、能够读取 SSID、且 SSID 与登记值逐字节匹配时，才返回该子应用配置的局域网 IP 和端口。未配置、蜂窝网络、未知 SSID、其他 Wi-Fi 均返回空值。IP 支持私有 IPv4 和 IPv6 地址。

代码工坊在进入、回到前台和网络配置变化时获取地址。取得地址后，电脑发现、列表、历史、模型、消息、图片与实时事件订阅全部使用该 Agent 的局域网 WebSocket，不需要登录 Hako 服务器，也不经服务器转发或认证。没有内网地址时使用原服务器连接。发送前再次核对网络，路由变化时取消旧请求并重新加载列表；不将未确认的写入自动重发到另一条路径。两种路径的本机缓存按连接上下文隔离。

Windows 1.1.0 的「服务器设置 → 局域网直连端口 → 保存局域网配置」可独立启用直连，不要求先配置服务器或密钥。端口默认 `0`，表示关闭；也可用 `Kage.exe config set --direct-port <端口> --json` 修改，用 `status --json` 查询实际监听状态。监听器只接收本机和本地网段的原生客户端，当前只开放代码工坊方法。请求和服务器路径共享同一套任务、队列与游标；关闭直连客户端不终止电脑任务。

直连客户端通过 `ws://<IP>:<端口>/workshop/v1` 同时发送请求和订阅增量事件；云端客户端通过 `/ws/workshop/client` 同时承载两者，Windows 的 `/ws/workshop/agent` 连接仍由守护进程持有。独立事件端点 `/workshop/v1/events/<operationId>/<cursor>` 和 `/ws/workshop/events/<computerId>/<operationId>/<cursor>` 继续提供原有用途。所有工坊端点使用 `hako.workshop/1`，拒绝设备监控的握手和请求帧。

Agent 从 `~/Code` 的一级 Git 项目构建应用列表，按会话实际工作目录关联应用。同一应用的会话放在同一个 Tab。显示不下的应用进入最后一个 Tab 的下拉菜单；发现新会话时，将其应用移到首位。聊天页顶部使用会话名称，正文只保留应用名和项目目录，应用名右侧显示模型；执行电脑在更多页面的会话信息中查看。

iOS 按登录上下文和执行电脑缓存应用、会话列表。进入页面、返回列表或切换电脑时先展示上次成功读取的列表，再立即刷新；停留列表时每次查询结束后间隔 3 秒继续刷新，进入会话后暂停列表轮询。最新一页读取成功后立即更新列表；普通轮询每 30 秒核对已加载的旧页，进入页面、手动刷新及本机归档操作仍立即核对。电脑列表每 10 秒核对一次，翻页不额外查询电脑列表；读取失败保留已显示内容并显示错误。缓存只表示历史内容，电脑在线状态仍需实时查询。每台电脑最多保存最近 300 条已加载会话，缓存使用系统文件保护且不参与云备份。

同步由代码工坊服务持有，不随对话页面关闭。返回会话列表后，最近打开的会话继续读取进度；离开整个代码工坊后，列表和会话继续同步一分钟，期间返回会直接复用原连接、对象、草稿、图片和事件游标。超过一分钟取消事件订阅；工坊在应用前台保留共享传输连接，进入后台或切换账号、网络路径时关闭，回到前台按需重建；五分钟未返回时释放保留的会话对象，最多保留六个。首次进入、离开较久、任务或完成轮次发生变化、连接异常或发送结果待确认时重新核对；切换登录上下文会停止旧任务并清空保留对象。主应用进入系统后台时暂停网络读取，回到前台按状态恢复，持续执行受 iOS 系统调度限制。

列表刷新保留同一任务已经确认的完成、失败或中断状态，旧的进行中快照不能覆盖终态；新的操作、更新时间或完成轮次仍可推进列表状态，新发送也会解除旧终态的限制。Agent 在同一轮次的执行进程已经结束后优先采用该任务的终态，避免元数据连接里滞留的进行中标记造成误报；仍在执行、收尾或排队的任务继续显示真实状态。

执行中的回复通过共享、已认证的 WebSocket 事件订阅推送：Agent 在文字增量、工具记录、审批或队列状态变化时唤醒订阅，合并 25 毫秒内的事件突发，服务端直接转发到 iOS，不再每秒查询任务。首次订阅及断线重连均携带最后已应用的事件文件字节游标，逐页补齐后继续等待新事件。手机按游标去重并保留正式轮次顺序；慢连接缓冲溢出时明确断开并从游标恢复，取消订阅只停止读取，不停止电脑任务。没有运行任务时仍定期核对会话历史，以发现其他客户端发起的变化；可见会话约每 10 秒核对，保留但不可见的会话约每 60 秒核对，运行中任务继续接收实时事件。已有任务的状态核对与历史读取并行，慢历史查询不阻塞任务状态。工坊查询和事件订阅不占用设备监控的请求槽；各自最多 16 个并发请求，在同一连接上按请求或订阅编号隔离结果。单次请求超时只结束该请求，不关闭共享连接，不自动重发写入；断线显示“正在恢复连接”，只有服务端明确报告电脑离线时才显示未连接。

共享订阅帧为 `{"kind":"watch","id":"订阅ID","computerId":"电脑ID","operationId":"任务UUID","cursor":0}`，取消使用 `{"kind":"unwatch","id":"订阅ID"}` 并收到 `unwatched` 确认；事件帧携带同一订阅 ID。切换会话只取消和新增相应订阅，不关闭底层连接。此客户端能力要求服务端/iOS `0.7.2`、Windows Agent `1.4.1`。

列表、历史和原型读取不恢复线程。发送时启动独立的 `codex app-server --listen stdio://`，恢复原 `threadId` 后开始一轮。新会话在发送第一条消息时创建。模型默认沿用 Codex 配置或原会话设置，可在会话右上角「更多 → 会话设置」选择。模型列表来自 App Server 的 `model/list`，实际可用性仍取决于本机账号和服务提供方。

会话顶部通过项目图标和名称颜色表示电脑连接状态，保留无障碍状态说明。右侧按「模型 · 速度 · 推理强度」显示摘要；速度沿用此会话已选择的档位，名称取自所选模型的速度目录，默认显示 Standard。模型和推理强度显示当前实际值，设置页未手动覆盖时也显示解析后的当前值。Agent 1.3.2 起，`history.read` 返回会话元数据中的 `model`、`reasoningEffort`，任务快照返回本轮已确认的模型和强度。运行中使用本轮快照，空闲时使用会话元数据；未确认的值明确显示待确认，不用模型目录的推荐默认值代替。设置变更仍在下一轮生效。

权限默认为自动审批（`workspace-write` + `on-request` + `auto_review`）。请求确认使用相同沙箱，由用户审批；完全访问使用 `danger-full-access` + `never`；跟随 `config.toml` 不覆盖本机权限配置。模型和权限变更在下一次发送时生效，原消息重试保留提交时的选择。

更多页面以原生下拉菜单选择模型、速度、Intelligence（推理强度）和权限。速度列表来自对应模型的 `serviceTiers`；Standard 明确传入 `serviceTier=default`，Fast 使用目录中的 `priority` ID。额外速度说明沿用 Codex 返回的内容。档位同时用于线程创建/恢复与本轮发送，并计入请求身份；切换速度后重试仍使用原消息的档位。

Intelligence 档位和说明取自模型的 `supportedReasoningEfforts`，保留目录顺序，不把可选档位写死。默认跟随会话已有配置；选择具体档位后，发送时通过 `turn/start.effort` 设置，新建和继续会话均适用。选择保存在会话设置和请求记录中，原消息重试不会使用后来修改的值；排队消息保存其选择，未覆盖时继承当前任务，Steer 不改变正在运行轮次的强度。切换模型后清除其不支持的档位。此功能需要 iOS 0.3.3 和 Agent 1.2.3，服务端继续原样转发既有接口。

输入框默认一行，最多展开五行。加粗加号位于输入框内部左侧，圆形发送图标位于右侧，执行中输入为空时切换为停止图标。每条消息可添加最多三张图片，也可仅发送图片。手机按最长边 2048 像素压缩为不超过 2 MB 的 JPEG，显示缩略图并支持移除；图片在同一条已认证 WebSocket 中用二进制帧上传，分片为 32 KiB，最多 4 片在途（128 KiB）。JSON 控制帧、消息流和图片共享连接并按编号隔离。上传前调用 `image.upload.begin`，用原图片 UUID、长度和 SHA-256 查询已落盘的连续进度；重试从缺口继续，接收端支持乱序与重复分片。网络中不再携带图片 Base64，守护进程到主进程的本机 JSON RPC 仍使用编码封装。图片保存在 Agent 配置目录的 `code-workshop/images`，以 `localImage` 输入发送给 Codex，不放入项目仓库。断线后可用原请求 ID 重试，重复分片不会追加重复内容。发送记录持久化后，消息立即进入消息流并在消息内显示上传进度，输入框清空后可继续输入；失败或取消时消息和图片保留在原消息中，重试使用同一请求 ID。原生文本框接收独立的文字与重置标识快照，附件栏收起时也必须应用文字清空；延迟的旧编辑回调不能恢复已发送内容。确认到达后如已输入新文字或更换图片，则保留新草稿。代码工坊本机日志分别记录确认核验、草稿清空和原生文本框重置，只记录请求标识、数量与匹配结果，不记录消息正文或图片内容。

桌面版处于空闲状态时仍可能持有写锁。实际恢复失败会显示桌面占用提示。任务结束后先关闭本轮子进程，释放线程写锁，再报告完成。恢复会话共享历史；桌面版内置浏览器等专属工具仍取决于宿主提供的能力。

执行中仍可输入文字和添加图片。发送后，消息立即出现在会话末尾并标记 `Queued`，等待期间始终排在最新回复和执行记录下方，多条消息保持原排队顺序。暂停、提交中或结果待确认的排队消息也保留在末尾；开始执行或 Steer 确认接收后退出排队区域。消息由 Windows Agent 持久化和按顺序续发，不依赖手机保持前台。每条排队消息右上角的菜单提供「修改消息」「Steer instead」和「取消消息」。修改保留队列位置；取消仅移除尚未发送的消息。Steer 使用当前活动轮次的 `turn/steer` 和 `expectedTurnId`，沿用本轮模型、速度及权限。接口确认接收后显示「Steer · 已接收」，不把接收等同于模型已经应用。

普通排队请求真正开始执行时，消息排在上一轮完整响应之后，并在自己的回复之前。历史合并按正式会话的消息顺序调整已存在的请求，不保留最初点击发送时的临时插入位置；这样下一条请求不会夹进上一轮的进度、执行记录和最终回复之间。

输入框为空时，右侧的同一个圆形按钮用于停止；输入文字或添加图片后切换为发送，没有独立的停止按钮。停止、失败或 Agent 重启后，未发送的队列保留并暂停，可修改、取消或手动发送。结果不确定的消息只提供核对结果；尚未确认进入 Agent 队列的消息可用原请求 ID 显式重试。

启动轮次和压缩上下文使用独立的 60 秒等待时间，普通查询仍为 8 秒。恢复会话期间回放的旧事件不计入新任务；轮次关联由启动响应或带本次消息 `clientId` 的输入事件确认，其他线程及轮次的事件会被忽略。若输入事件已确认接收，即使启动响应超时也继续监听执行结果，不因响应延迟关闭任务进程。异常、重启后查询任务或刷新历史时，Agent 按持久化消息 ID 查找原始轮次，分页核对真实结束状态并保存修正结果；不会根据相同文本或最新轮次猜测结果，也不会自动重发消息。

## 会话消息缓存

打开已有会话时，iOS 先从本地显示已缓存的消息、执行记录、原型卡片和后续消息状态，再异步读取最新历史并按消息 ID 合并。已加载的较早消息继续保留；若缓存尾部与最新一页之间有缺口，会在后台分页补齐。下拉刷新和回到前台沿用相同流程，网络读取失败保留当前内容。

缓存同时保存任务 ID、事件字节游标和流式文字累加器，并作为一个文件原子写入。再次进入时从已保存游标继续读取；新任务从头读取事件时，不会将已有历史回复重复拼接。缓存只用于展示，任务、审批及消息菜单的可操作状态仍需在线核对。

消息按服务器登录上下文、执行电脑、应用与会话分别隔离。文件启用系统文件保护且不参与备份，编码和写盘在后台串行执行。每个会话最多缓存最近 300 条消息、文件不超过 2 MiB；每个登录上下文最多保留 50 个会话、合计不超过 64 MiB，超出时淘汰较旧缓存。丢弃流式累加器时同步重置其游标，以便安全重读。

## 请求与恢复

不同会话的执行任务不设全机固定并发数量上限；新任务和暂停消息的恢复都不会因为其他会话正在执行而被拒绝。同一会话继续通过追加或排队处理后续消息，避免启动互相冲突的执行任务。归档中的会话单独提示等待归档完成。

### 快捷命令

会话右上角「更多」菜单按分组直接列出已保存的快捷命令和快捷提示词，分组之间使用原生菜单分隔线；设置和压缩上下文也位于此菜单。命令库初始为空，由用户在「更多 → 设置 → 编辑快捷命令」新增、编辑和删除；快捷提示词通过相邻的「编辑快捷提示词」管理。两类条目按服务器、电脑和项目保存在手机，不同步为电脑端预置脚本。点击菜单中的提示词，直接将提示词文字发送到当前会话，保留输入框中的草稿和待发送图片；已有任务时沿用会话的排队发送流程，失败时可从消息记录重试。点击命令则发送名称、完整 PowerShell 内容、项目、超时秒数及唯一请求 ID，工作目录为所选项目。命令不修改会话草稿，也不向 Codex 发送消息。

### 项目文件浏览与编辑

会话右上角的文件夹按钮以 sheet 打开项目文件浏览，外观跟随系统。下划线标签依次为「所有文件」「已修改」；前者按需展开目录，后者显示项目 Git 状态中的暂存、未暂存、未跟踪及已删除文件。底部提供搜索和本次浏览中的最近文件。搜索最多扫描 20,000 项并保留 200 个匹配，Git 修改列表最多保留 200 项；达到限制或部分目录不可读时显示提示。目录和结果均分批读取，不传输 `.git` 内部内容。

打开文本文件直接复用容器管理的 `HakoCodeEditor`，提供行号、语法高亮和键盘快捷操作。支持不超过 256 KiB 的 UTF-8（含 BOM）及带 BOM 的 UTF-16 文本，保存保留原编码与换行；二进制、超大文件、链接和只读文件不可编辑。已删除文件保留状态展示。返回时对未保存内容提供保存并继续、放弃修改和继续编辑。

Agent `1.4.16` 起提供 `files.list`、`files.modified`、`files.read` 和 `files.write.begin/chunk/commit`，iOS `0.8.47` 接入。请求沿用工坊通道，服务端不解释文件命令。文件读取和写入使用 8 KiB 分块与 SHA-256 校验；提交时再次核对读取基线并原子替换文件。并发修改时保留手机草稿并拒绝覆盖；提交回执丢失时标记结果待确认，只允许重新读取核对，不自动重试写入。路径必须位于所选项目，拒绝越界路径、链接和 Git 内部路径。

快捷命令需要服务端/iOS `0.3.0` 和 Windows `1.2.0`。主 Agent 的 `commands.open` 复用或启动守护进程，并按需开启其内部的命令管理模块，不再启动单独的命令执行器宿主。守护进程使用独立程序文件，持有单独的 `/ws/workshop/command-agent` 云端连接和带随机凭据的本机 WebSocket；手机仍通过认证工坊客户端连接调用云端。iOS `0.8.63` 和 Agent `1.4.19` 起，手机局域网请求复用配置的工坊直连端口，由主 Agent 通过带凭据的环回连接转交守护进程，手机不再访问执行器的随机端口或缓存其凭据。电脑端凭据用 DPAPI 保护，每次转交都核对执行器进程和账号范围；转交不重发写入请求，保留原请求 ID 和错误。主 Agent 退出、程序替换和重连不停止守护进程中的命令任务，局域网日志读取在主 Agent 恢复后继续。

| 方法 | 参数与结果 |
| --- | --- |
| `commands.open` | 主 Agent 启用守护进程的命令模块，返回局域网端口与凭据 |
| `commands.start` | `requestId`、`applicationId`、`name`、`command`、`timeoutSeconds`、`allowBackgroundProcesses`；返回持久化任务，包含提交时的后台进程选项 |

同一电脑一次执行一条命令。命令最长 8,000 UTF-8 字节，超时范围 1–86,400 秒，使用 PowerShell 7 非交互模式。任务、命令快照、退出码和最多 20 MiB 日志保存在 Agent 配置目录；手机前台每秒读取增量，没有进行中任务时停止轮询。关闭页面或手机断网不停止命令；再次打开可查历史。相同请求 ID 和参数只执行一次，参数冲突明确拒绝；网络结果不确定时保留原请求，可显式重试核对。

命令子进程进入独立 Windows Job，执行器保持在 Job 外。更新脚本进入替换阶段前，可在 `KAGE_COMMAND_TASK_DIRECTORY` 下持有独占 `phase.lock`，检查不存在 `cancelled` 后写入 `installing` 标记；该阶段禁止手动停止，超时最多额外等待三分钟。通过 `KAGE_COMMAND_EXECUTABLE --launch-agent --target <新程序> --data-dir <配置目录> --json` 启动新 Agent，使其脱离命令 Job，避免脚本结束时随子进程退出。这些环境变量由执行器传入，不要求手机预置任何命令。命令运行时不会自动提升 Windows 权限。

每条快捷命令提供「允许后台进程继续运行」，新命令默认关闭。开启时，提交命令仍受停止和超时控制，其启动的子进程独立运行，不随提交命令结束、停止或超时被清理。该模式适用于提交独立后台任务，例如 `xkode tasks submit`；后台任务的日志和取消由对应工具管理。任务记录保存提交时的开关值，修改命令或重试不能改变已接收任务的运行方式。

当前兼容版本线为服务端/iOS `0.3.x` 和 Agent `1.2.x`，最低分别为 `0.3.0` 和 `1.2.0`。命令数据和 `commands.start` 请求必须显式提供布尔字段 `allowBackgroundProcesses`；不再补齐旧字段或自动重写旧格式。新建命令仍默认关闭该选项。

命令管理模块与守护的更新、异常恢复循环分别运行，首次使用后随守护进程保留。守护进程收到停止或更新请求时停止接收新任务，现有任务仍可读取日志、查询和取消；全部完成后才关闭命令连接并退出。`install-guardian.ps1` 等待该过程结束后替换守护程序，必须从独立终端或更新器运行，不能由它自身托管的命令同步等待自身退出。守护进程或命令模块异常退出时，未完成记录在下次启动时标为中断，不会自动重跑。此机制能承受主 Agent 替换，不能承受电脑关机或守护进程被强行终止。

新增 Agent 能力均为 v1。

提交立即返回任务 ID，执行生命周期属于 Windows Agent。手机断网、后台挂起和服务端连接重建不会取消已提交任务。iOS 在前台通过工坊专用事件连接接收增量，回到前台后沿用游标继续读取。

会话底部状态显示当前轮次的处理时长，执行中每秒更新，完成或停止后保留总耗时。任务摘要的 `startedAt` 是当前轮次开始处理的 Unix 秒数，`finishedAt` 是已确认终态的 Unix 毫秒数；执行中和结果未知时 `finishedAt` 为 `null`。排队任务尚未开始时 `startedAt` 为 `0`，实际开始或手动续发时重新记录，等待用户确认的时间计入处理时长。补充到正在执行轮次的引导消息不重置计时。重新进入会话后读取电脑上持久化的时间，缺少准确时间时不显示耗时。此响应字段从 Agent `1.2.5`、iOS `0.4.1` 开始使用，服务端消息转发协议不变。

### 后台任务通知

工坊设置的「后台任务通知」默认关闭，由用户主动开启。开启时复用主应用的系统通知授权、远程通知注册和 Hako Device Token 上报；订阅按已认证的 Console 公钥保存到服务器。系统通知许可本身不会启用工坊通知。设置同时显示服务器 APNs 配置和此设备登记是否就绪，网关仍沿用当前一台接收 iPhone 的限制。

Windows 在任务记录中保存所属云端身份（服务器 origin、账号、公钥的摘要）、终态时间和服务器确认。只有 `completed`、`failed`、`interrupted`、`unknown` 进入待上报记录；等待确认、排队、暂停、Steer 已接收和收尾不算完成。正常完成要等 Codex 子进程关闭、线程写锁释放后再上报。Agent 重启时，原执行中任务转为结果未知，未发送队列保留暂停，不伪报成功。

每个实际执行的请求独立去重，队列续发的轮次分别通知；Steer 合入当前轮次，不额外报告一次完成。

终态通过 Windows 独立的、RSA 已认证的工坊云端 WebSocket 上报，不依赖手机连接或事件订阅。服务器从握手身份确定执行电脑，复核当前连接和公钥信任；帧只允许上报状态、时间、项目名、会话名和助手回复摘要，不能指定接收设备、其他电脑或任意 APNs 字段。持久化成功（包括明确跳过）才返回确认。确认丢失或电脑断网后重连可重报；服务器用电脑 ID 与任务 UUID 生成确定性通知 ID，在现有 APNs 队列事务内去重。已跳过的事件也保存回执，之后开启开关不会补发旧通知。

**局域网直连发起的任务也支持通知**：只要 Windows 配置了 Hako 云端账号，它和云端请求使用同一套任务记录，Windows 经独立云端工坊连接上报。手机直连仍无需认证，请求、图片、回复仍走局域网。仅配置局域网端口、没有云端账号，或者 Windows 无法联网时，不能实时通过 APNs 推送；已有云端身份的任务可在恢复同一云端连接后补报，终态超过 15 分钟则记录过期并跳过，不补发陈旧提醒。切换服务器、账号或公钥不会把旧任务发给新身份。

通知标题为「代码工坊 · 项目名」，副标题为会话名，正文包含完成、失败、中断或结果未知的状态与本轮最后一条已完成助手回复的摘要。摘要压缩空白、移除内部原型引用，最多 240 个 Unicode 字符，超过时以省略号结尾；无已完成回复时只显示状态，不借用前一轮回复、用户提问或工具输出。项目名最多 80 字符，会话名最多 120 字符；服务器校验边界并保证 APNs payload 不超过 4096 字节，不上传完整工作路径或原始错误详情。名称和回复摘要会经 Hako 服务器、Apple Push 传递，也可能显示在锁屏上，设置页说明了这一点。App 处于前台时显示紧凑的应用内顶部消息横幅，只显示项目名和会话名，使用代码工坊图标，不显示状态、正文摘要、时间或关闭按钮，向上滑动关闭。点按横幅打开可回复的会话预览 Sheet，右上角关闭返回原页面，左上角“切换”进入完整会话；预览和完整会话复用同一会话对象、消息和草稿。预览不改变底层页面的项目或电脑选择，且只有预览会话计为当前正在阅读的会话；后台或被系统终止时由 APNs alert 展示，无需 iOS 后台常驻。点按通知定位对应电脑和会话，实际结果仍需在线读取电脑任务。通知受系统授权、专注模式、网络与 Apple 投递影响，不能保证即时到达。

沿用现有 APNs 发送语义：排队持久化，成功响应仅标为 `provider_accepted`，不代表已展示、收到或已读；无凭据、设备未登记/失效、超时和 APNs 拒绝明确记录失败。发送途中网关重启或网络中断标为 `unknown`，不自动重发，避免重复提醒。关闭开关抑制尚在队列的工坊通知；已交给 Apple 或已开始发送的通知无法撤回。当前网关使用已有 `direct_push` 表保存工坊投递及去重记录，无需迁移数据库。

此接口扩展对应服务端/iOS `0.2.1`、Windows `1.1.1`，三端更新后方可启用；源码版本号变化不表示已部署。上线前需人工核对 APNs 凭据与接收设备状态，并在明确授权后执行真实推送验收。

iOS 在发送前持久化原请求 ID 和原参数。重复的同一请求返回原任务，复用 ID 提交不同内容会报错。新线程取得 `threadId` 后，重试仍保留原来未指定线程的参数。网络结果不确定时先查询原任务，用户可显式重试原消息；不会自动重发。

Agent 按自身配置目录持久化任务元数据和事件。Agent 重新启动后，未确认完成的旧任务标为结果未知，要求读取 Codex 会话核对。审批回复只授予本次操作。未支持的交互请求会明确拒绝并在会话显示提示。

## 异步提问与回答

Codex 的 `agentMessage.delivery=async` 和结构化 `questions` 会随历史与实时事件一起传给手机。每条消息保留最多三个问题、每题八个选项，也支持没有选项的自由填写。会话内显示回答卡片，选项不会自动提交；填写完整后点按「提交回答」。回答作为普通会话消息持久化，关联原问题 ID，沿用原请求 ID 重试；活动轮次通过 Steer 接收，已结束的轮次按现有续发流程处理。手机的其他输入草稿不被覆盖。取消尚未发送的回答后可重新作答，已保存的回答会显示对应发送状态。

提问不等待任务结束才通知。Agent 保存每条提问的上报记录，并沿用已认证工坊连接和服务端 APNs 队列；问题 ID 与任务 ID 一起参与去重，同一任务的多条提问及任务完成提醒互不覆盖。提问通知类型为 `workshop_question`，包含定位用的电脑、线程、任务和问题 ID，以及有长度限制的问题摘要。通知遵守已有工坊通知开关、设备登记、有效期及发送结果不确定时不自动重发的规则。前台显示应用内消息横幅，后台显示系统 Push，点按后进入对应会话作答。

本次扩展采用服务端/iOS `0.3.1`、Agent `1.2.1`，三端同步升级；没有增加旧接口回退。工坊事件增加可选 `questions`（`title`、`options`）和 `questionId`；`turn.start`、`message.queue` 的回答携带原问题 ID，用户消息回执与历史保留该关联。通知帧的 `questionId` 在提问时非空，并在 ACK 中原样返回；`result` 增加 `threadId`、`questionId`，提问状态为 `input_required`。任务终态的 `questionId` 为空。

## 工坊帧格式

握手返回 `{"kind":"welcome","protocol":"hako.workshop/1"}`。查询采用 `{"kind":"call","id":"请求ID","computerId":"电脑ID","method":"history.read","params":{}}`，成功返回 `kind=result` 和 `result`，失败返回 `kind=failure` 和 `error={code,message}`。事件帧为 `kind=event` 和 `result`，不使用设备监控的 `type/request/version/body` 格式。

Windows 云端终态帧为 `{"kind":"terminal","operationId":"任务UUID","result":{"state":"completed","finishedAt":1794441600000,"projectName":"hako","sessionName":"本轮迭代","summary":"已完成修复并通过测试。"}}`，时间为 Unix 毫秒。项目名、会话名必须非空；无已完成回复时摘要为空字符串，不接受缺少名称的旧版终态事件。此通知内容契约采用服务端/iOS `0.3.0`、Windows `1.2.0`，三端同步升级。服务器返回 `{"kind":"terminal_ack","operationId":"任务UUID"}` 表示事件已接收或按订阅策略跳过，不表示 Apple 已接受或手机已展示；帧只能走 Windows 认证连接，不能由 iOS 请求通道提交。

Windows 云端连接使用独立 RSA-PSS 挑战，签名绑定 `hako-workshop-auth/v1`、服务器 origin、账号、公钥指纹和随机数。只为工坊登记在线状态；设备监控连接的建立、断开或请求满载不会修改该状态。电脑撤销信任时，两项服务各自断开自己的连接。

## 原型预览

原型卡片从 Codex 的可视化引用、HTML 文件链接和文件修改记录生成。读取范围限于会话项目和当前用户的 Codex 原型目录，并拒绝目录链接。文件不超过 2 MB，分块读取并核对 SHA-256。每次打开重新读取并校验文件，传输期间使用同一份不可变修订快照，避免混合修改前后的字节；快照失效后文件修订不一致时要求重新打开。

iOS 使用独立的临时 WebKit 数据存储预览 HTML。HTML 片段补齐页面和基础样式；页面内交互在预览中运行。页面不获得 Hako 凭据、原生调用接口或本机文件访问。预览支持静态及自包含原型，网络接口和本地开发服务器需要独立的预览代理。

## 验证

### 查询与同步诊断

Agent 的 Codex 查询连接按请求 ID 并发处理不同读取；同时发生的相同读取合并执行，单个客户端取消等待不取消其他客户端的读取。列表使用最多四路并发读取摘要，已稳定且元数据不变的非运行会话摘要最多缓存 30 秒；列表翻页在 30 秒内复用同一份排序元数据，避免逐页扫描全部会话。历史直接分页读取上游消息，每次最多读取 64 个原始条目，不再获取完整线程或完整轮次；最多复用四个会话在最近 30 秒内读取的分页快照。游标包含线程身份、原始条目位置及同轮次发送回执去重状态，刷新最新一页或 Agent 重启后仍保持翻页位置。刷新最新一页始终重新查询，不复用已完成请求的结果。查询超时不销毁仍正常工作的共享连接。

图片和原型下载共用最多四个在途分片的传输额度，上传也使用该额度，为消息和状态读取保留请求槽。原型重新打开时先校验修订，不变时复用手机缓存。Agent 的下载快照最多保留 30 秒、四份且合计不超过 24 MiB，同一传输仅整文件读取和计算 SHA-256 一次；失效后重新读取并校验修订。下载取消会清理所有在途分片，不影响共享连接和电脑任务。

Agent 数据目录的 `code-workshop/queries.jsonl` 记录查询方法、初始化等待耗时 `waitMs`、RPC 耗时 `readMs` 和结果分类，达到 1 MB 后轮换至 `.previous`。日志不写参数、消息正文、响应内容或凭据。手机端区分查询超时、网络中断、电脑离线和本机会话服务暂不可用；同步历史失败时仍独立核对任务状态，避免将未同步误报为任务执行失败。

连接诊断同时覆盖手机、服务端与 Agent。Agent 数据目录的 `logs/workshop-connection.jsonl` 和 `logs/command-workshop-connection.jsonl` 分别记录工坊与命令连接的建立、失败阶段、异常类型、关闭码、连接时长及恢复耗时。服务端标准日志使用 `workshop_socket` 前缀，记录各自的连接编号、读取/发送/心跳失败、协议帧拒绝、连接替换和订阅积压，不输出原始异常描述或数据帧内容。

三端诊断最终汇总到 Agent 数据目录的 `logs/remote-workshop.jsonl`，每条保留来源与原始发生时间。手机按服务器账户独立保存最多 512 条未确认记录，在会话请求成功后分批调用 `diagnostics.append` 上报；每批最多 8 条，成功确认后才删除，失败保留待下次补传。该命令在守护进程直接落盘，主 Agent 暂时不可用时仍可接收；局域网直连时由主 Agent 接收。服务端不解释这个设备命令。

从服务端 0.7.5、Agent 1.4.5 起，Agent 在已认证工坊握手中声明 `diagnostics: true` 和已落盘的 `cursor`，服务端沿同一连接发送 `kind: diagnostics` 批次，每批最多 16 条。服务端数据库旁的 `.workshop-diagnostics.jsonl` 保留诊断积压，内存最多保留最新 1,024 条，连接恢复后按游标补传。Agent 持久化服务端游标，手机记录按 UUID 去重。日志文件达到 1 MiB 后轮换至 `.previous`，积压与去重窗口均有上限，不保证无限期离线的完整历史。上报不包含消息、图片、命令正文、Token、请求头或完整 URL；接收端只保留允许的诊断字段。上报失败不会触发会话重发，也不会递归生成新的请求失败报告。

Windows `Hako.Checks code-workshop` 使用真实 stdio 子进程夹具验证线程关联、重复请求、断连后继续执行、审批、停止、持久化、事件游标、写锁冲突和原型修订校验。`code-workshop-local <状态目录>` 只读验证已安装的 Codex；`code-workshop-local-turn <状态目录>` 提交固定短回复并归档测试会话，仅用于明确授权的本机联调。

iOS `WorkshopModelTests.swift` 验证请求身份和恢复参数；`WorkshopRequestSocketTests.swift` 与 `WorkshopEventStreamTests.swift` 独立验证握手、帧格式、回复关联、推送和取消，不依赖设备监控传输。服务端验证工坊满载和任一连接关闭时，另一应用仍可请求。iOS 工程编译验证全部 SwiftUI 与 WebKit 页面。

后台通知回归不使用真实凭据或平台请求：`go test ./...` 包含并发重复事件、重开数据库、关闭订阅后的发送前复核、过期、设备/凭据不可用及 APNs 中断不重发；`Hako.Checks workshop-notifications` 验证待上报记录、身份隔离和重启恢复，`workshop-cloud` 验证没有 iOS 订阅时的独立终态/确认协议，`code-workshop` 用假 Codex 验证实际任务完成、失败、中断及排队状态。默认 Windows 检查和现有 CI 自动覆盖上述检查。iOS `RemoteNotificationPolicyTests.swift` 验证前台应用内横幅的通知分类、提问与会话定位、后台通知点击和原构建通知行为。

二进制传输能力要求服务端/iOS `0.7.3`、Windows Agent `1.4.2`。二进制 WebSocket 帧前四字节为大端路由头长度，随后为含 `id` 和 `computerId` 的 UTF-8 JSON 路由头（不超过 1 KiB），其余为不透明载荷。服务端只校验路由和帧大小，关联请求 ID 后转发，不解析图片协议。图片载荷为 36 字节 UUID、4 字节大端分片偏移和最多 32 KiB 原始 JPEG 字节；完成确认发生在所有分片落盘、SHA-256 与 JPEG 边界校验并原子转为最终文件后。取消仅终止手机侧在途请求，已接收数据保留供续传，且不会启动模型任务。
