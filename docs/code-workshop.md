# 代码工坊

代码工坊通过 Windows 应用中的独立工坊服务使用本机 Codex CLI App Server。它拥有独立的 hako.workshop/1 协议、WebSocket 连接、请求池和在线状态，不借用设备监控协议或 Agent 连接。账号登录和已登记的电脑公钥仍由 Hako 主应用管理。电脑需要在当前 Windows 用户下安装并登录 Codex CLI。

当前按 Codex CLI 0.164.0 的本机协议验证。含后台任务通知的工坊需要服务端 0.2.1、Windows 1.1.1 和 iOS 0.2.1，三端需协同升级，不回退到设备监控通道。

代码工坊支持最新消息摘要、进行中标记和未读标记。列表读取最新轮次的摘要，跳过工具记录，按最近更新时间倒序排列。未读按电脑、会话及完成轮次在手机本地保存，最后更新超过 12 小时后不再显示标记；列表停留期间也会定时更新过期状态。会话位于前台、最新消息可见时清除未读，上滑阅读历史、查看弹出详情或切到后台时保留标记。

列表状态由最新轮次和 Agent 实际执行中的任务决定。线程本身的 `active` 标记不会覆盖最新轮次的完成、失败或中断结果；本机任务仍在等待确认或释放写锁时，继续显示实际任务状态。

会话行左滑露出橙色归档按钮，点击后归档，不支持整行滑到底直接执行。左上角会话数量菜单可切换已归档列表，再左滑取消归档。进行中、排队和暂停的会话不能归档，电脑离线或归档提交中禁用操作；列表右侧不再显示更多按钮。

## 会话与应用

### 局域网直连

iOS 主应用「设置 → 网络 → 网络配置」统一管理内网 Wi-Fi 名称与子应用 IP、端口，目前支持代码工坊。原应用更新区域的网络检测与 Wi-Fi 配置移到此处，已登记的 Wi-Fi 自动保留。应用更新继续使用同一份内网判断。

主应用通过 `LocalNetworkProviding.endpoint(for:)` 提供地址：只有当前连接 Wi-Fi、能够读取 SSID、且 SSID 与登记值逐字节匹配时，才返回该子应用配置的局域网 IP 和端口。未配置、蜂窝网络、未知 SSID、其他 Wi-Fi 均返回空值。IP 支持私有 IPv4 和 IPv6 地址。

代码工坊在进入、回到前台和网络配置变化时获取地址。取得地址后，电脑发现、列表、历史、模型、消息、图片与实时事件订阅全部使用该 Agent 的局域网 WebSocket，不需要登录 Hako 服务器，也不经服务器转发或认证。没有内网地址时使用原服务器连接。发送前再次核对网络，路由变化时取消旧请求并重新加载列表；不将未确认的写入自动重发到另一条路径。两种路径的本机缓存按连接上下文隔离。

Windows 1.1.0 的「服务器设置 → 局域网直连端口 → 保存局域网配置」可独立启用直连，不要求先配置服务器或密钥。端口默认 `0`，表示关闭；也可用 `Hako.exe config set --direct-port <端口> --json` 修改，用 `status --json` 查询实际监听状态。监听器只接收本机和本地网段的原生客户端，当前只开放代码工坊方法。请求和服务器路径共享同一套任务、队列与游标；关闭直连客户端不终止电脑任务。

直连接口为 `ws://<IP>:<端口>/workshop/v1`（请求与电脑信息）及 `/workshop/v1/events/<operationId>/<cursor>`（增量订阅）。云端由 Windows 独立连接 `/ws/workshop/agent`，iOS 独立连接 `/ws/workshop/client` 与 `/ws/workshop/events/<computerId>/<operationId>/<cursor>`。所有工坊端点使用 `hako.workshop/1`，拒绝设备监控的握手和请求帧。

Agent 从 `~/Code` 的一级 Git 项目构建应用列表，按会话实际工作目录关联应用。同一应用的会话放在同一个 Tab。显示不下的应用进入最后一个 Tab 的下拉菜单；发现新会话时，将其应用移到首位。聊天页顶部使用会话名称，正文只保留应用名和项目目录，应用名右侧显示模型；执行电脑在更多页面的会话信息中查看。

iOS 按登录上下文和执行电脑缓存应用、会话列表。进入页面、返回列表或切换电脑时先展示上次成功读取的列表，再立即刷新；停留列表时每次查询结束后间隔 3 秒继续刷新，进入会话后暂停列表轮询。最新一页读取成功后立即更新列表，再核对已加载的旧页；读取失败保留已显示内容并显示错误。缓存只表示历史内容，电脑在线状态仍需实时查询。每台电脑最多保存最近 300 条已加载会话，缓存使用系统文件保护且不参与云备份。

同步由代码工坊服务持有，不随对话页面关闭。返回会话列表后，最近打开的会话继续读取进度；离开整个代码工坊后，列表和会话继续同步一分钟，期间返回会直接复用原连接、对象、草稿、图片和事件游标。超过一分钟取消事件订阅，传输连接按空闲策略回收；五分钟未返回时释放保留的会话对象，最多保留六个。首次进入、离开较久、任务或完成轮次发生变化、连接异常或发送结果待确认时重新核对；切换登录上下文会停止旧任务并清空保留对象。主应用进入系统后台时暂停网络读取，回到前台按状态恢复，持续执行受 iOS 系统调度限制。

执行中的回复通过专用、已认证的 WebSocket 事件订阅推送：Agent 在文字增量、工具记录、审批或队列状态变化时唤醒订阅，合并 25 毫秒内的事件突发，服务端直接转发到 iOS，不再每秒查询任务。首次订阅及断线重连均携带最后已应用的事件文件字节游标，逐页补齐后继续等待新事件。手机按游标去重并保留正式轮次顺序；慢连接缓冲溢出时明确断开并从游标恢复，取消订阅只停止读取，不停止电脑任务。没有运行任务时仍定期核对会话历史，以发现其他客户端发起的变化。工坊查询和事件订阅不占用设备监控的请求槽；各自最多 16 个并发请求，拥有独立的心跳和重连。

列表、历史和原型读取不恢复线程。发送时启动独立的 `codex app-server --listen stdio://`，恢复原 `threadId` 后开始一轮。新会话在发送第一条消息时创建。模型默认沿用 Codex 配置或原会话设置，可在会话右上角「更多 → 会话设置」选择。模型列表来自 App Server 的 `model/list`，实际可用性仍取决于本机账号和服务提供方。

权限默认为自动审批（`workspace-write` + `on-request` + `auto_review`）。请求确认使用相同沙箱，由用户审批；完全访问使用 `danger-full-access` + `never`；跟随 `config.toml` 不覆盖本机权限配置。模型和权限变更在下一次发送时生效，原消息重试保留提交时的选择。

更多页面以原生下拉菜单选择模型、速度和权限。速度列表来自对应模型的 `serviceTiers`；Standard 明确传入 `serviceTier=default`，Fast 使用目录中的 `priority` ID。额外速度说明沿用 Codex 返回的内容。档位同时用于线程创建/恢复与本轮发送，并计入请求身份；切换速度后重试仍使用原消息的档位。

输入框默认一行，最多展开五行。加粗加号位于输入框内部左侧，圆形发送图标位于右侧，执行中输入为空时切换为停止图标。每条消息可添加最多三张图片，也可仅发送图片。手机按最长边 2048 像素压缩为不超过 2 MB 的 JPEG，显示缩略图并支持移除；图片通过原有认证通道以 9 KiB 分片上传，按 UUID、偏移量和 SHA-256 校验、去重。图片保存在 Agent 配置目录的 `code-workshop/images`，以 `localImage` 输入发送给 Codex，不放入项目仓库。断线后可用原请求 ID 重试，重复分片不会追加重复内容。

桌面版处于空闲状态时仍可能持有写锁。实际恢复失败会显示桌面占用提示。任务结束后先关闭本轮子进程，释放线程写锁，再报告完成。恢复会话共享历史；桌面版内置浏览器等专属工具仍取决于宿主提供的能力。

执行中仍可输入文字和添加图片。发送后，消息立即出现在会话末尾并标记 `Queued`，等待期间始终排在最新回复和执行记录下方，多条消息保持原排队顺序。暂停、提交中或结果待确认的排队消息也保留在末尾；开始执行或 Steer 确认接收后退出排队区域。消息由 Windows Agent 持久化和按顺序续发，不依赖手机保持前台。每条排队消息右上角的菜单提供「修改消息」「Steer instead」和「取消消息」。修改保留队列位置；取消仅移除尚未发送的消息。Steer 使用当前活动轮次的 `turn/steer` 和 `expectedTurnId`，沿用本轮模型、速度及权限。接口确认接收后显示「Steer · 已接收」，不把接收等同于模型已经应用。

普通排队请求真正开始执行时，消息排在上一轮完整响应之后，并在自己的回复之前。历史合并按正式会话的消息顺序调整已存在的请求，不保留最初点击发送时的临时插入位置；这样下一条请求不会夹进上一轮的进度、执行记录和最终回复之间。

输入框为空时，右侧的同一个圆形按钮用于停止；输入文字或添加图片后切换为发送，没有独立的停止按钮。停止、失败或 Agent 重启后，未发送的队列保留并暂停，可修改、取消或手动发送。结果不确定的消息只提供核对结果；尚未确认进入 Agent 队列的消息可用原请求 ID 显式重试。

## 会话消息缓存

打开已有会话时，iOS 先从本地显示已缓存的消息、执行记录、原型卡片和后续消息状态，再异步读取最新历史并按消息 ID 合并。已加载的较早消息继续保留；若缓存尾部与最新一页之间有缺口，会在后台分页补齐。下拉刷新和回到前台沿用相同流程，网络读取失败保留当前内容。

缓存同时保存任务 ID、事件字节游标和流式文字累加器，并作为一个文件原子写入。再次进入时从已保存游标继续读取；新任务从头读取事件时，不会将已有历史回复重复拼接。缓存只用于展示，任务、审批及消息菜单的可操作状态仍需在线核对。

消息按服务器登录上下文、执行电脑、应用与会话分别隔离。文件启用系统文件保护且不参与备份，编码和写盘在后台串行执行。每个会话最多缓存最近 300 条消息、文件不超过 2 MiB；每个登录上下文最多保留 50 个会话、合计不超过 64 MiB，超出时淘汰较旧缓存。丢弃流式累加器时同步重置其游标，以便安全重读。

## 请求与恢复

新增 Agent 能力均为 v1。

| --- | --- |

| `turn.start` | 用客户端请求 ID 提交一轮 |
| `operation.read` | 用字节游标读取持久化的回复增量、执行记录、状态和审批 |

提交立即返回任务 ID，执行生命周期属于 Windows Agent。手机断网、后台挂起和服务端连接重建不会取消已提交任务。iOS 在前台通过工坊专用事件连接接收增量，回到前台后沿用游标继续读取。

### 后台任务通知

工坊设置的「后台任务通知」默认关闭，由用户主动开启。开启时复用主应用的系统通知授权、远程通知注册和 Hako Device Token 上报；订阅按已认证的 Console 公钥保存到服务器。系统通知许可本身不会启用工坊通知。设置同时显示服务器 APNs 配置和此设备登记是否就绪，网关仍沿用当前一台接收 iPhone 的限制。

Windows 在任务记录中保存所属云端身份（服务器 origin、账号、公钥的摘要）、终态时间和服务器确认。只有 `completed`、`failed`、`interrupted`、`unknown` 进入待上报记录；等待确认、排队、暂停、Steer 已接收和收尾不算完成。正常完成要等 Codex 子进程关闭、线程写锁释放后再上报。Agent 重启时，原执行中任务转为结果未知，未发送队列保留暂停，不伪报成功。

每个实际执行的请求独立去重，队列续发的轮次分别通知；Steer 合入当前轮次，不额外报告一次完成。

终态通过 Windows 独立的、RSA 已认证的工坊云端 WebSocket 上报，不依赖手机连接或事件订阅。服务器从握手身份确定执行电脑，复核当前连接和公钥信任；帧不允许指定接收设备、其他电脑或通知正文。持久化成功（包括明确跳过）才返回确认。确认丢失或电脑断网后重连可重报；服务器用电脑 ID 与任务 UUID 生成确定性通知 ID，在现有 APNs 队列事务内去重。已跳过的事件也保存回执，之后开启开关不会补发旧通知。

**局域网直连发起的任务也支持通知**：只要 Windows 配置了 Hako 云端账号，它和云端请求使用同一套任务记录，Windows 经独立云端工坊连接上报。手机直连仍无需认证，请求、图片、回复仍走局域网。仅配置局域网端口、没有云端账号，或者 Windows 无法联网时，不能实时通过 APNs 推送；已有云端身份的任务可在恢复同一云端连接后补报，终态超过 15 分钟则记录过期并跳过，不补发陈旧提醒。切换服务器、账号或公钥不会把旧任务发给新身份。

通知区分完成、失败、中断和结果未知，只含固定状态文案与电脑/任务标识，不包含提问、回复、工作路径或错误详情。App 处于前台时不弹工坊横幅；后台或被系统终止时由 APNs alert 展示，无需 iOS 后台常驻。点按通知打开代码工坊，实际结果仍需在线读取电脑任务。通知受系统授权、专注模式、网络与 Apple 投递影响，不能保证即时到达。

沿用现有 APNs 发送语义：排队持久化，成功响应仅标为 `provider_accepted`，不代表已展示、收到或已读；无凭据、设备未登记/失效、超时和 APNs 拒绝明确记录失败。发送途中网关重启或网络中断标为 `unknown`，不自动重发，避免重复提醒。关闭开关抑制尚在队列的工坊通知；已交给 Apple 或已开始发送的通知无法撤回。当前网关使用已有 `direct_push` 表保存工坊投递及去重记录，无需迁移数据库。

此接口扩展对应服务端/iOS `0.2.1`、Windows `1.1.1`，三端更新后方可启用；源码版本号变化不表示已部署。上线前需人工核对 APNs 凭据与接收设备状态，并在明确授权后执行真实推送验收。

iOS 在发送前持久化原请求 ID 和原参数。重复的同一请求返回原任务，复用 ID 提交不同内容会报错。新线程取得 `threadId` 后，重试仍保留原来未指定线程的参数。网络结果不确定时先查询原任务，用户可显式重试原消息；不会自动重发。

Agent 按自身配置目录持久化任务元数据和事件。Agent 重新启动后，未确认完成的旧任务标为结果未知，要求读取 Codex 会话核对。审批回复只授予本次操作。未支持的交互请求会明确拒绝并在会话显示提示。

## 工坊帧格式

握手返回 `{"kind":"welcome","protocol":"hako.workshop/1"}`。查询采用 `{"kind":"call","id":"请求ID","computerId":"电脑ID","method":"history.read","params":{}}`，成功返回 `kind=result` 和 `result`，失败返回 `kind=failure` 和 `error={code,message}`。事件帧为 `kind=event` 和 `result`，不使用设备监控的 `type/request/version/body` 格式。

Windows 云端终态帧为 `{"kind":"terminal","operationId":"任务UUID","result":{"state":"completed","finishedAt":1794441600000}}`，时间为 Unix 毫秒。服务器返回 `{"kind":"terminal_ack","operationId":"任务UUID"}` 表示事件已接收或按订阅策略跳过，不表示 Apple 已接受或手机已展示；帧只能走 Windows 认证连接，不能由 iOS 请求通道提交。

Windows 云端连接使用独立 RSA-PSS 挑战，签名绑定 `hako-workshop-auth/v1`、服务器 origin、账号、公钥指纹和随机数。只为工坊登记在线状态；设备监控连接的建立、断开或请求满载不会修改该状态。电脑撤销信任时，两项服务各自断开自己的连接。

## 原型预览

原型卡片从 Codex 的可视化引用、HTML 文件链接和文件修改记录生成。读取范围限于会话项目和当前用户的 Codex 原型目录，并拒绝目录链接。文件不超过 2 MB，分块读取并核对 SHA-256；文件在读取期间改变时要求重新打开。

iOS 使用独立的临时 WebKit 数据存储预览 HTML。HTML 片段补齐页面和基础样式；页面内交互在预览中运行。页面不获得 Hako 凭据、原生调用接口或本机文件访问。预览支持静态及自包含原型，网络接口和本地开发服务器需要独立的预览代理。

## 验证

Windows `Hako.Checks code-workshop` 使用真实 stdio 子进程夹具验证线程关联、重复请求、断连后继续执行、审批、停止、持久化、事件游标、写锁冲突和原型修订校验。`code-workshop-local <状态目录>` 只读验证已安装的 Codex；`code-workshop-local-turn <状态目录>` 提交固定短回复并归档测试会话，仅用于明确授权的本机联调。

iOS `WorkshopModelTests.swift` 验证请求身份和恢复参数；`WorkshopRequestSocketTests.swift` 与 `WorkshopEventStreamTests.swift` 独立验证握手、帧格式、回复关联、推送和取消，不依赖设备监控传输。服务端验证工坊满载和任一连接关闭时，另一应用仍可请求。iOS 工程编译验证全部 SwiftUI 与 WebKit 页面。

后台通知回归不使用真实凭据或平台请求：`go test ./...` 包含并发重复事件、重开数据库、关闭订阅后的发送前复核、过期、设备/凭据不可用及 APNs 中断不重发；`Hako.Checks workshop-notifications` 验证待上报记录、身份隔离和重启恢复，`workshop-cloud` 验证没有 iOS 订阅时的独立终态/确认协议，`code-workshop` 用假 Codex 验证实际任务完成、失败、中断及排队状态。默认 Windows 检查和现有 CI 自动覆盖上述检查。iOS `RemoteNotificationPolicyTests.swift` 验证前台抑制、后台通知点击和原构建通知行为。
