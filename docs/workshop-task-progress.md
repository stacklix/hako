# 会话任务进度

代码工坊通过通用任务数据展示后台工作，不执行项目构建命令。iOS 共用 TaskProgressCard 展示最近一次构建的阶段、版本和安装检查结果。

代码工坊在输入框上方固定显示当前会话最近 10 轮已开始对话中引用的最近一次构建，展示应用名、当前阶段和状态；点击后通过 Sheet 查看阶段详情、变更摘要、错误及安装入口。不按构建时间过期；构建所属轮次移出最近 10 轮后隐藏状态栏并关闭详情，排队中、尚未开始的消息不计入轮数。消息渲染器在后台增量索引最近 10 轮的任务引用，复用未变化消息的索引；状态栏只匹配任务 ID，不扫描历史，也不跟随消息滚动。进度由独立视图持有，前台每 3 秒通过现有连接查询 tasks.list，详情展开时继续刷新，离开页面或进入后台后暂停；内容不变的响应不发布更新。

## 数据流

用户级 `build-progress` skill 包装已有命令或监控构建工具，原子写入 `$CODEX_HOME/task-progress/<会话 UUID>/<任务 ID>.json`（未配置 CODEX_HOME 时使用用户 `.codex` 目录）。Windows 后台 worker 使用独立隐藏的计划任务，结束后清理自身登记；聊天回合结束或 Agent 更新不会终止采集。

Agent 经已有鉴权/直连通道提供 `tasks.list {threadId}`，仅返回同一会话的有界数据，不增加服务端业务接口，不执行文件中的命令。iOS 在会话可见且前台时独立刷新；退出页面停止请求。构建监控继续运行，再次进入可恢复终态。活动任务 60 秒没有更新时显示“进度暂未更新，结果待确认”。

记录格式：

```json
{"schema":1,"threadId":"会话 UUID","task":{"id":"task-id","name":"应用或任务名","project":"项目名","platform":"iOS","status":"running","createdAt":1790000000000,"updatedAt":1790000000000,"stages":[{"id":"build","name":"编译","status":"running"}],"message":null,"release":null}}
```

状态为 `queued/pending/running/succeeded/failed/cancelled/unknown/skipped`。只记录真实阶段，不从聊天文本或任意日志推断百分比。监控失败不重复提交原构建。公共记录不含命令、凭据和原始日志；worker 配置与日志在独立 `_workers` 子目录中，不返回客户端。

## 安装动作

任务的可选 `summary` 字段保存变更摘要（不超过 500 字符，单行），显示在应用和版本信息下方；`message` 继续用于执行状态说明。摘要来自提交时的 `--summary` 或工作流配置，由生产端提供，不从聊天或命令输出生成。

xkode 任务以确认安装成功作为进度完成，不将启动计入阶段或进度分母。启动结果保留在原始构建任务中；已知启动失败可单独提示，但不会将安装成功的任务改为失败。安装失败仍显示失败。构建、签名、打包成功的产物可提供安装动作，即使后续安装失败。

成功任务可提供 `release {bundleId,version,build,metadataUrl}`。HTTPS `metadataUrl` 返回 `version/build/manifest`；manifest 是同目录文件，包含匹配应用标识、构建号和 HTTPS IPA 地址。安装前重新读取元数据和 manifest，阻止跨应用包、未发布版本及降级；已有更新发布时确认最新目标。

宿主只能直接确认自身的本机版本，其他 App 的安装版本保持未确认，并由用户决定是否请求安装。确认后再次核对发布信息，使用系统 `itms-services` 入口；系统接受请求只显示“已请求安装”，不视为安装成功。项目地址、应用标识、版本、阶段均来自任务数据，组件不包含具体项目规则。
