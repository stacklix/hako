# Cerno A 股选股

Hako iOS 的「金融 → A 股选股」是独立原生子应用。业务、模型、网络适配和本机偏好均在 `apps/ios/Hako/Features/StockTrade/`；主应用仅登记入口，共享服务负责 HTTP、安全存储、Hako 身份和首次授权界面。不会引用投资记账或加密资产的业务代码。

## 连接与登录

在右上角滑杆设置中填写 Cerno 的 HTTPS 后端基础地址和公开的 Hako 应用 `clientId`。基础地址可为域名根地址，也可包含应用子路径，例如 `https://example.com/cerno/`；客户端会在其后追加 `/api/v1/`，因此填写时不再追加 API 路径。此时登录、会话、选股、行情和提醒均请求 `/cerno/api/v1/…`。设置中同时显示用于 Hako 登记的根来源 `https://example.com`，授权按该根来源和 Client ID 核对，不把业务路径作为来源。

后台需部署 Cerno API v1、登记相同的 HTTPS 根来源，并配置 Hako issuer、应用 Secret 和后台会话加密密钥。同域名下不同应用分别登记，使用各自 Client ID 和 Secret；业务路径由反向代理路由到对应后端。手机不接收后台凭据，也不使用 Hako Agent 或 `X-Proxy` 转发业务请求。基础地址不允许账号、查询、片段、路径跳转或歧义编码；末尾斜杠统一移除。本机会话、自选及通知偏好按包含路径的完整后端地址隔离，切换路径不会复用另一应用的令牌。

在 Hako「第三方应用 → Cerno → 配置登录方式」开启「原生授权」。仅使用原生接入时，扫码登录和 OIDC 可保持关闭；应用总开关仍须启用。

手机生成随机 PKCE verifier，调用 Cerno `POST /api/v1/auth/native/start`，把响应 `requestId` 映射为共享原生授权请求的 `id`。客户端分别核对 meta、start 和 Hako 的登记、nonce、挑战、期限及当前 Console 上下文；首次需要显式确认，不能自动把 `consent:false` 升级为 `true`。再向 Cerno `native/complete` 提交 `loginId,code,codeVerifier`，只保存 Cerno 自己的 Bearer 令牌。

会话与设备凭据保存在本设备钥匙串，不经 iCloud 同步。Hako 仅在首次或重新登录时证明身份；Cerno 在本地维护 12 小时访问令牌，后续查询、续期和退出都不连接 Hako。已有 Cerno 会话不会因为 Console 临时离线或重新登录而失效；切换 Hako 服务器或 Cerno 连接时仍隔离可见账号与偏好。

首次生成随机 UUID（ThisDeviceOnly），对 UUID、规范化后端基础地址和应用 ID 求 SHA-256，作为设备指纹。`native/start` 提交 `deviceFingerprint`；初次 PKCE 兑换返回 `deviceId`、随机 `deviceToken` 和访问令牌。服务端对指纹再次求 SHA-256，同时只存设备密钥和访问令牌摘要。钥匙串会话使用 v2 命名空间，不恢复旧的无设备凭据记录。

访问前对临近到期令牌提前续期；重新打开应用时可凭已过期的访问令牌记录内的设备凭据续期，无需 Hako 在线。`POST /cerno/api/v1/auth/native/refresh` 使用设备 ID、设备密钥和指纹，无固定续期截止时间；同设备未被退出或撤销就可持续续期。并发请求合并续期请求，401 后只续期并重试一次；任务写入携带绑定参数的请求 UUID，重试不会重复创建任务。Cerno 网络故障保留账号、历史数据与设备凭据；明确 401 后停止自动恢复并要求用户主动重新登录。

退出调用 `POST /cerno/api/v1/auth/native/logout`，撤销当前设备及其访问令牌，成功后删除本地会话；设备 UUID 保留以便之后重新登记。退出不依赖 Hako，也不撤销其他设备或 Hako Console。通用 Hako 身份证明协议不变；本地续期由 Cerno 自己提供。

## 页面与数据口径

- 选股：最新完整运行、候选及推荐数量、发布/数据时间、原始规则门槛；正式推荐、全部候选、各观察池与排除明细。保留后台顺序和缺失分数，手机不重新评分。
- 单股：同一快照的日/周 K 线、成交量、日线知行短期与多空线、可独立开关的周线 MA5/10/20/60。支持 60/120/250 根或全部历史、长按十字读数、双指及按钮缩放、逐根无障碍读数、原始复评及风险。
- 关注：按 `(backend,issuer,subject)` 隔离的本机关注与已发布证券搜索，不会自动启用后台监控。
- 监控：独立入口展示规则观察、模拟持有与模拟结束；提醒记录与详情保留邮件投递状态，不把邮件成功说成推送送达或券商成交。
- 工作台：完整选股与分步操作、任务记录、阶段与日志、失败后重新运行、发布记录及选定历史结果。空快照时可直接启动完整选股。
- 健康：分别展示调度/行情/提醒/状态时间和完整选股发布日期，不以 HTTP 存活或页面打开推断业务正常。

列表首屏读取后用明确 runId、snapshotId 与原游标继续分页。刷新重新获取首屏；旧数据与当前错误同时保留，不将失败显示为空成功。行情按后端 `date_desc` 校验并反转绘图，不反转股票排名。跨快照、重复日期、非法 OHLC、单位或周期口径不符的数据拒绝绘图。未完成周线明确标注；周桶为 W-FRI。成交量为手（100 股），成交额为千元，缺失时不估算。

当前前复权为 `qfq/source_cache`，后端尚未验证整段复权基点。页面始终保留该限制，不作为已验证回测数据。只有已发布的日/周行情，无实时或分钟报价。`bars.items[].lines` 由后端在完整不可变历史上、分页前计算，日线字段为 `short/long`，周线为 `ma5/ma10/ma20/ma60`，缺少预热样本的指标保留 null。手机不根据已载入页重新估算。打开和刷新页面不会启动扫描、回测或盘中任务。

## 手动选股与发布

`POST /cerno/api/v1/tasks` 提交 `kind`（`full/fetch/preselect/review/publish`）与 `requestId`（UUID）；完整选股和初选可指定 `dataDate`，默认最新可用交易日。相同账号、UUID 和参数重放返回原任务，参数变化或存在其他活动任务返回 409。`GET /tasks` 支持 `limit/cursor`，`GET /tasks/{id}` 返回持久状态、阶段、固定文案日志和发布结果。原生请求使用 Cerno Bearer；网页提交仍须同源 Cookie 与 CSRF 头。

状态为 `queued/running/succeeded/failed`。任务由数据执行端 Python 服务调度，界面只提交与读取；关闭界面不会取消。完整流程取得原有数据工作流锁后执行行情、初选、复评和完整快照发布，分步操作不会隐式执行后续步骤。上游原始输出保留于后台私有日志，不通过 API 返回。中断状态不自动重跑；需确认工作进程和子进程均已结束后才允许新任务。

执行端需显式启用 `workflow_enabled: "true"` 并安装完整 Python 依赖。只读快照 API 保持关闭执行能力。手机任务列表与进度在前台轮询，切换账号或连接清空可见任务；返回应用后从后台恢复状态。

## 页面结构与 Hako 样式

任务详情持续展示最近一条后台进展、更新时间和已运行时长；执行日志保留阶段内的行情检查／处理数量、复评数量及限流重试提示。百分比只对应当前处理步骤，阶段之间不拼接为预计总进度。后台每 60 秒没有业务进展时报告进程仍在运行与无进展时长，便于区分处理缓慢与尚未返回。

客户端沿用已确认的 Cerno 原型页面结构，视觉样式与 Hako 的投资记账、青龙等子应用保持一致：复用 `HakoStyle` 背景、卡片与中性色，重要操作使用默认 `HakoActionButtonStyle`，14pt 卡片圆角、16pt 内容内边距；去掉品牌眉题与独立蓝色主题，标题使用支持动态字体的系统样式。

原型示例不作为业务数据：快照只提供收盘价时，列表明确标注「收盘 / 元」，不填示例涨跌幅；推送仍显示未接入，通知偏好仍明确标注未同步后台。调度信息仅展示实际返回的字段，不补造心跳或定时计划。

## 设置层级

工具栏打开「Cerno 设置」首页，连接分组只显示「连接设置」入口。后端基础地址、Hako 登记来源、公开应用 ID 与填写说明放在二级连接页；该页右上角勾号保存，校验失败时原地显示错误。返回时有草稿会询问是否放弃，关闭或下滑整个设置弹窗继续由 `SettingsSheet` 保护未保存修改。设置首页没有保存按钮；账号与授权、选股说明、通知和后台状态各自分组展示。

## 设置中的选股说明

设置首页提供「选股说明」分组，三个只读入口在未登录或离线时也能阅读：

- **业务流程**：以编号卡片和箭头展示抓取行情、策略初选、逐票复评、校验发布；说明产出、失败分支、后台继续执行、分步操作与监控的关系。
- **选股策略**：分层展示流动性池、B1 回撤、B2 量价确认、Brick 可选策略、四维复评权重、排序与风控、名单分层。条件默认折叠，显示的固定数值明确标注为参考配置，不伪装成在线配置。
- **术语说明**：按行情与指标、策略与评分、任务与结果分组，可搜索中文、英文及解释。区分规则评分、排序分与风险分，说明行业百分位是行业之间的相对强弱，说明快照、数据日期和纸面持仓的含义。

策略页末直接展示已载入快照的日期、发布时间、过期标记和实际门槛；查看历史结果时明确标注「所选历史结果」，没有结果时显示空状态，不填入参考门槛。进入说明页不触发行情请求、登录、任务提交或发布，也不改变设置草稿。

说明依据 Cerno 的 `pipeline/fetch_kline.py`、`pipeline/pipeline_core.py`、`pipeline/select_stock.py`、`pipeline/selector.py`、`agent/base_reviewer.py`、`agent/review_scorecard.py`、`pipeline/tasks.py` 与 `pipeline/published.py`，并核对 `config/rules_preselect.yaml`、`config/code_review.yaml`。后台策略变化时需同步更新说明，当前复评是确定性代码执行，不调用 AI 模型。

## 通知配置的实际边界

提醒页铃铛和连接设置都可打开原生通知配置 Sheet。邮件已有后台发送与重试能力；当前冻结业务 API **没有通知偏好写入、推送订阅和测试投递端点**。

此版本按账户保存本机邮件偏好、事件类别、交易日限制、上海时间跨夜免打扰和同股票同事件间隔，并明确标注「本机偏好 · 尚未同步后台」。这些值不会改变邮件队列或后台调度。手机推送显示尚未接入，不申请无用途的设备权限；测试只预览内容，不真实投递。没有伪造已启用或已送达状态。

后续落地需要 Cerno 明确通知偏好读写契约与作用范围，并将事件路由到 Hako 通用通知入口，完成设备订阅和 APNs 投递、撤销、重试/去重及送达状态协议后再开放推送开关。Python 继续拥有任务和邮件重试调度职责。

## 验证

`StockTradeModelsTests.swift` 覆盖快照、单位、行情合法性、空字段、均线与通知时段；`StockTradeSessionTests.swift` 使用假 Hako 与假 Cerno 验证显式同意、单次兑换、持久会话恢复、401/503、退出不确定、身份切换、固定快照与直连请求头。macOS CI 编译执行两组测试；模块边界由 `test_subapp_boundaries.py` 检查。

`StockTradeRoutingTests.swift` 验证根地址与多级应用路径下所有类型请求的 URL 拼接、授权根来源、规范编码、请求头及路径越界拦截，已接入 macOS CI，也可使用 Linux Swift 工具链运行。会话测试同时覆盖同域名不同路径之间的令牌、自选和通知偏好隔离，以及切回相同规范路径后的独立恢复。

真实端到端验收仍需部署支持通用原生授权的 Hako 服务与 Cerno API、相互一致的 HTTPS 应用登记，以及完整的数据/监控快照。测试数据不能证明生产授权、真实行情、邮件或推送送达成功。
